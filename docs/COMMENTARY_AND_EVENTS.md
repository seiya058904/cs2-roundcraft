# 解说素材、语义节拍与事实引用

## 用户指定的优先级

1. 五批字幕整理语录共 1,283 条：第一批 364、第二批 448、里约 Day3 197、里约决赛 134、沃斯堡 140；原始材料共 1,294 条，排除明细见 `data/normalized/quotes-manifest.json`。满足场景门的语录同级优先于原创模板。
2. 四份 JSONL：468 条明确标注原创的中文比赛模板，含用户提供的原有 360 条，以及本地补写的 84 条阶段表达、24 条情境短开头；后两批单独标为 `assistant-authored-original-template`。
3. 根据当前事件生成的事实表达。

最高优先级仍以场景匹配为前提。每条启用语录都有显式条件，五回合内同句冷却；冷却期间使用其他符合条件的语录或较低优先级模板。不会为了“用完素材”强行套用特定人物、地图、比分、特殊动作或对未来赛果的判断。

原语录稿说明其来自 B 站 AI 字幕，做过错字修正与口语碎片合并。本项目保留该说明及比赛出处，未逐字听录认证。用户提供的“真实语录”与先前“原创模板”在数据层明确分开，不混称。

`scripts/import-quotes.mts` 按 RQ、RB、RD、RF、RW 命名空间生成稳定 ID，原文不替换绰号，编号不重排。原有 812 条的全部字段保持不变。后续批次与全部已有批次归一化去重，忽略标点、空格、大小写；包含关系仅在较短文本至少十字时判重。原始包文件保留，排除不等于删除来源。`src/domain/realQuotes.ts` 定义实际场景门，材料 beat 标签本身不授权播放。原345条逐句历史条件见 [第九轮清单](COMMENTARY_QUOTE_REVIEW_ITERATION9.md)，其后修改以第十至十二轮报告为准；初次接入见 [新三包接入迭代报告](COMMENTARY_ITERATION_NEW_PACKAGES.md)。

## 从事实到解说

比赛引擎先生成事件。`deriveCommentaryBeats` 提取开局计划、经济差、首杀、补枪、人数变化、残局、爆头、道具、下包、赛点与收尾等语义节拍；然后根据显著性与段数预算选择连续中文。普通回合主要事件最多六段，高光回合九段，另保留开局与收尾。

每个节拍只引用时间不晚于它的已发生事件，同秒也按事件先后顺序取证。解说选择独立于比赛随机流，回放、快进、改变播报速度不改变赛果。当前计划引擎先呈现情绪语录，再接具体事实句，保留实际选手、人数或比分；已有旧引擎继续沿用原来的生成方式和存档指纹。

计划引擎记录实际拆包开始、中断与完成，开始事件关联已下的包、拆包者和真实工具；仅在事件发生后播报，拆包期间的击杀可区分拆包者与队友。火焰致死和道具换人按真实伤害来源叙述，不称为枪械补枪。仅具备特殊事实条件的残局开始节拍提高优先级，仍受同一段数、冷却和事实规则约束。

解说段落保存 `eventIds`、`sourceBeatIds`，使用素材时保存 `templateId`；用户真实语录另保存比赛出处 `quoteSource`。真实语录后接原创阶段事实句时，另记 `supportTemplateId`，辅助句也执行同回合去重及五回合冷却，不冒用真实语录出处。UI 可展开事件依据与语录出处。所有文本经 React 文本输出，不使用 HTML 注入。

阶段表达按结构化规则与状态选择，区分等烟、恢复推进、主动过烟、来不及等烟、集结、执行、留道具、恢复道具、留守、回防与清点。回合结束的指令清理不另播一次动作；同队同秒的集结结束与推进启动合并为一次启动。普通回合阶段最多两段，高光最多三段。详细和精简均使用口语事实句，不直接念引擎状态说明。当前节奏证据与剩余缺口见 [阶段解说迭代报告](COMMENTARY_ITERATION_RHYTHM.md)。

`causal-story-10` 一轮进一步把同次击杀的首杀/补枪、闪光转化、混烟、爆头与对狙事实合到一个段落。主句仍独立选择符合条件的语料，相关节拍和事件依据保留在 `sourceBeatIds`、`eventIds`；不同击杀不会仅因同秒发生而合并。多杀汇总、残局人数变化有独立信息，不视为一次新的单杀。赛点、换边、加时提示必须在比分收尾后出现，精简模式也保留，全部精简片段仍最多五段；提示占用原有选段预算。详见 [整回合衔接迭代报告](COMMENTARY_ITERATION_FLOW.md)。

`causal-story-11` 一轮沿用地图胜负函数补充加时赛点、加时换边、再次加时、守住赛点、地图/系列赛结束；开局压力仅取回合开始比分。败方残局只在残局开始后实际完成过击杀、且没有保枪存活时补点评；“最后暂停”候选只取当时的额度与历史前缀，回放不读未来暂停。新增接线和多赛制证据见 [决胜阶段迭代报告](COMMENTARY_ITERATION_ENDGAME.md)。

第七轮版本为 `causal-story-12`。普通回合的原创开头按已结束回合的连分或接近比分选择短句，不再固定轮换两段通用长开头；真实语录仍优先。合段动作也可从已经保留的附加节拍选真实语录，每句继续通过各自原有事实门，并保留该节拍的依据与出处。普通控图开头不进入两次手枪局；“补枪杀人捡枪”还要求捡到该次补枪击杀掉落的武器。证据和候选池见 [高频口语迭代报告](COMMENTARY_ITERATION_VARIETY.md)。

第八轮历史版本为 `causal-story-13`。14 类阶段即使素材全部冷却，也使用结构化状态对应的口语事实，不退回内部日志；同一人的死亡中断多个规则时只补报一次。当前残局“没钳没烟”按事件前缀检查库存，精简存档也不得含未填变量。闪光与接枪用有实际事件依据的“第一时间/第二时间”串联。两小时以上的迭代验收与边界见 [阶段验收](COMMENTARY_ACCEPTANCE.md)，完整文字样本见 [审读样本](COMMENTARY_ACCEPTANCE_SAMPLES.md)。新包仍有345条未逐句接线、even仍缺自然播出证据；精确对账和新增混烟验证见 [语料对账与接入缺口](COMMENTARY_CORPUS_ACCOUNTABILITY.md)，不将阶段里程碑等同于全量完成。

## 三层阅读

- 现场解说：按用户选择的节奏逐段显示，可立即展开。
- 战术复盘：解释胜利条件、双方战术、交火与移动次数。
- 精确账本：事件时间、参与者、地点、伤害与详细字段，以及双方完整经济账本。

## 绰号仅限解说

用户后续提供 `nickname-map.md`，并明确更正：**只改变游戏解说中的称呼，不改选手名字。** 因此阵容、选手档案、统计、排名、赛程与技术事件参与者继续显示真实英文名；只有解说正文应用 `首选绰号（职业名）`，队伍称呼沿用已确认映射。

映射包含 42 位选手、12 支队伍；当前阵容快照匹配 37 位选手。多绰号只使用第一项，例如载物（ZywOo）、小孩儿（m0NESY）。大小写差异不创建新身份，京介/京芥、表哥/大表哥分别匹配；没有映射的继续用英文名。“小夫”、空白或待核对项不绑定人物。

旧存档只在解说显示时应用新称呼，不修改内部 ID、原始名字、阵容或已保存事件。语录出处维持原始比赛名称，便于核对资料。映射为用户指定的解说用语，不冒充独立核验的身份资料。

## 检查

`npm run sim:commentary` 验证每段引用、回放相等、无未填变量、无未来事实引用、随机状态不变，并报告实际启用素材和文本长度。只报告实际触发的数量，不把“导入 724 条”冒充“所有句子均已触发”。

尚无语音合成、真人声音克隆或音频播放；这是纯文字现场解说。

## 用户补充风格指南

`data/source/commentary-style-guide.md` 保存用户提供的风格分析；其中语料数量和词频是用户材料中的统计，本项目未重新核验全部原始字幕。应用重点为：道具与补枪、可核对的时间差、少用重复呐喊、高光才使用强烈比喻。五批语录在场景满足时同级优先于原创模板，来源字段不变。

当前计划引擎的经济语录按购买后的实际装备类别判断，不能拿 `auto` 或未买成的购买意图代替实际装备。具名语录还需对应真实参与者，烟、钳子、持枪等条件只读取事件前缀。高光呐喊有独立候选分支，复用已有多杀、残局获胜或经济逆转的事实，不增加一次相同高光的播报。近五回合已用过的固定解释段暂不复用；事实句继续正常给出。

当前增加闪光转化击杀、烟灭火、补枪秒差与拆包剩余秒数。每条只引用此前已发生事件。现场存活、位置、HP 随已播报的事件前缀重建；现金与护甲等未完整记录中间变化的值在结算前隐藏。可手动逐段或立即展开，不消耗比赛随机流。

强烈呐喊以最近三回合为一组冷却，比喻以最近十回合为一组冷却；同一回合至多各使用一次，且需多杀、残局翻盘或经济逆转事实条件。这是游戏节奏控制，不是对原字幕词频的精确拟合。

用户在三小时收尾时进一步要求绰号后加职业名注释，优先于风格素材中的不附英文要求。新生成与旧存档显示均执行此规则，并保持重复格式化幂等。身份数据不变。
