**可工程化的解说特征**（观察性总结，不是原话）：

- **先给局势，再给镜头：**“{T}选择控制中路 → {CT}某处只剩单人 → 镜头给突破手”，让观众知道这一枪为什么重要。
- **预告风险、保留问号：**“会不会直接爆？”“他敢不敢拉？”不能装作提前知道尚未发生的结果。
- **即时状态更新：**击杀发生后快速交代五打四、三打三、包的位置、剩余时间，而不是只喊人名。
- **因果句多于流水账：**说明“烟挡住回防”“没有补枪导致人数丢失”“首杀打开转点空间”。
- **节奏对比：**默认期低声分析，接敌突然加速，名场面可以高声连续反问，结束后回归经济与策略。
- **有控制的喜剧反差：**先夸技术判断，下一枪空了立刻反转；吐槽针对比赛操作，不编造选手人品或赛外故事。
- **熟悉选手和地图：**理解爆弹、补枪、反清、绕后、假打、时间管理、低装备翻盘的区别。可以使用绰号，但应有独立的准确选手映射。

**建议分布（可配置）**：一局普通回合中，40% 事实推进、30% 战术因果、20% 悬念/点评、10% 情绪反应；高光回合可将情绪反应上调，低行动回合保持克制。这是为模拟器设计的经验参数，**不是玩机器本人说话比例的测量值**。

## 三、原创场景化语料（180 条，可直接改写和调用）

**统一模板槽位：**

- `{T}`：当前回合进攻方战队，例如黑豹 FURIA；`{CT}`：当前回合防守方，例如小蜜蜂 Vitality。半场交换后必须重新绑定。
- `{P}`、`{Q}`：此事件中的两个关联选手，不必固定属同一阵营；生成前必须按事件校验身份和生死状态。
- `{STAR}`：当前比赛重点选手，只能在场且符合场面时使用。
- `{POS}`：具体点位，如 A 大、A1、VIP、香蕉道、铁板；`{SITE}`：A/B 包点；`{ENTRY}`：进入包点的通路；`{MAP}`：当前地图名称。
- 以下各条的“触发条件”是**必要场景提示**，不是充分条件。生成器仍须核验地图、时间、人数、武器、回合状态，否则宁可少说一句。
- 强度 **1=轻声铺垫，2=正常分析，3=紧张提速，4=激昂，5=极高光**；强度 5 不应连续占满一个普通回合。

### 01. 赛事开场与总体局势

001. 好，双方已经进入服务器了，今天这场{T}打{CT}，我觉得真正要看的还是两边第一波正面碰撞。  
   *条件：比赛开场、双方阵容确定；强度：2*
002. 比赛来到了{MAP}，{T}先打进攻，{CT}先守，地图选择本身就已经有说法了。  
   *条件：地图确定、攻守已知；强度：2*
003. 这张地图不能光看谁枪硬，外场的第一轮信息怎么拿，决定了后面整回合敢不敢动。  
   *条件：存在外围控图要点；强度：2*
004. 双方开局比分是零比零，最先交出来的东西不是战术，是心态和对枪的自信。  
   *条件：开局、零比零；强度：2*
005. 你说{T}有机会吗？当然有，问题是他们能不能把优势回合稳稳装进口袋。  
   *条件：两队实力接近或弱队挑战强队；强度：2*
006. 镜头给到了{STAR}，今天他要是能把这个位置打开，{CT}的防线就很难完整。  
   *条件：明星突破手在主攻区域；强度：2*
007. 我最想看的反而是{CT}的中期调整，第一套东西被人看穿之后，他们有没有第二套？  
   *条件：预期战术针对性较强；强度：2*
008. 来，看这个出生点，{P}明显靠前，{T}会不会围绕他来打第一波节奏？  
   *条件：进攻方有明显优势出生点；强度：2*
009. 好，场面上暂时没发生什么，但这不是没东西，双方第一分钟就在交换信息。  
   *条件：回合开局无交火；强度：1*
010. 先别急着下结论，这张图打到后半段，经济和地图控制才会把真实差距体现出来。  
   *条件：上半场初段、局势未明；强度：1*

### 02. 手枪局与初始博弈

   *条件：手枪局、慢开；强度：2*

   *条件：手枪局、闪光配合准备；强度：3*
014. 四个人往{SITE}走了，这个时候防守队员最怕的不是一个人，是四个枪线同时出来。

## 五、给赛事模拟 Agent 的使用规则

### 1. 解说应消费事件，而不是随意编比赛

一条引擎事件建议包含：

```json
{
  "event_id": "round_01_event_05",
  "map": "de_dust2",
  "round": 1,
  "phase": "live",
  "round_time_remaining_sec": 72,
  "side_t": "FURIA",
  "side_ct": "Vitality",
  "alive_t": 4,
  "alive_ct": 4,
  "bomb_state": "carried",
  "bomb_carrier": "T_PLAYER_04",
  "event_type": "flash_then_duel",
  "actor": "CT_PLAYER_02",
  "target": "T_PLAYER_01",
  "zone": "A_LONG",
  "utility": "flash",
  "observed": true,
  "consequence": "trade_kill",
  "economy_state": "pistol",
  "visible_information": ["A_LONG_contact", "T_reinforcements_unknown"]
}
```

这里采用**虚构玩家 ID**；实际运行需要用玩家 ID 映射真实名单，再映射绰号。不能把 `T_PLAYER_04` 硬替换成某个现实职业选手。

### 2. 推荐的两段式叙事

第一段是**先说明发生了什么**，第二段是**解释局势为什么变了**：

- **锚点**：谁在什么位置，拿什么道具/武器，进攻还是防守。
- **短预判**：说明一两种可能走向，如“会不会冲烟”“要不要转点”。
- **实际结果**：由引擎返回击杀、撤退、下包、拆包、超时等结果后，再生成惊叹与人数更新。
- **转化**：对同一事件解释战术因果，再提下一步悬念。
- **收尾**：比分、经济、下一回合的局势；没有确认就不乱报。

如果模拟器一次只生成一小段战况，也要在内部保留**上一场面**，避免一个句子说进攻下包、下一句又说进攻还在携包转点。

### 3. 推荐触发优先级与防重复

1. **最高优先级**：爆点、首杀、连续击杀、残局 1vN、下包、拆包、回合结束、赛点结果。
2. **中优先级**：假打成功、关键道具、多人回防、拿到地图控制、强起翻盘、经济损失。
3. **低优先级**：默认站位、空窗期、赛前背景、普通经济分析。

建议：常规回合选 6–10 个有意义的事件播报，低动作回合更少；首杀后尽量有一次状态更新；同一个原句至少冷却 5–8 回合，夸张口癖、绰号梗和强度 5 的句子不要连续刷屏。这是游戏设计建议，不是实测本人语速。

### 4. 事实一致性检查（发布前必须做）

- 【人数】死亡后不得再次击杀；人数始终从 5/5 起算，每次正确更新；已经死的选手不准出现在活人镜头。
- 【身份】交换攻守后重算 `{T}`、`{CT}`；同一玩家 ID 的队伍和选手姓名始终一致；不要把“装包方”误当作防守方。
- 【炸弹】未携包、包落地、正在下包、已下包、已拆除、已爆炸各自互斥；只有已下包才能出现拆包与爆炸倒计时。
- 【时间】所有“剩十秒”“没有钳子来不及”均依赖真实计时与拆包信息；不确定就不报具体秒数。
- 【武器】没有狙就不能播大狙击杀；无烟不能突然封烟；没有闪不能突然把人闪白。
- 【地图】地图名和点位必须匹配；不存在的通道不能生成；地图池变化时以游戏内配置为准。
- 【战术】“假打成功”必须有对方被牵制或回防证据；否则只能说“可能是假动作”。
- 【数值】“Top 1”“四杀”“三连胜”“第六个赛点”等必须来自输入数据，不得凭语气编造。
- 【赛果】常规先达 13 回合才赢图；12:12 后是否加时依具体赛制；赢一张图不等于赢完整 BO3。
- 【归因】不能只根据一枪输赢断言选手性格或全场状态；玩梗要受证据和情境约束。

### 5. 建议的风格生成主提示词（原创用途）

> 你是中文 CS2 电竞赛事模拟器的文字解说系统。借鉴高水平中文 CS 解说的实时推进方式：紧贴镜头、先给战术判断、再由比赛事件修正判断；有时连续短句、反问、惊叹；精彩回合情绪自然上扬，平淡回合仍保持清晰专业。不必每句重复“好”“喔”，不可为追求节目效果虚构击杀、装备、经济、时间或战术信息。每段解说提供“当前发生的事”和“对局势意味着什么”，根据比赛强度动态增减篇幅。将玩机器作为**风格研究参考**而非本人代言身份；不得宣称这些原创句子为本人真实说过的话。严格消化事件状态与可见信息，再挑选、改写本语料库的对应场景台词，必要时生成全新而不重复的表达。

### 6. 赛制、队伍、语音的工程化注意点

- 将比赛模拟的**队伍能力**与**选手能力**分层：团队执行力、信息协同、道具质量、地图熟练度、经济管理、临场调整，对应个人枪法、走位、突破、架狙、残局、抗压与稳定性。解说应描述发生的**实际结果**，不要把这些能力评分直接念出来。
- 同一“枪法数值 95”在不同场景下应该产生不同叙事：高位首杀、盲狙极限、多杀拯救、打赢被闪的反应枪；但不保证每次都触发，**比赛结算与解说文本解耦**。
- 口头连接词可以随机化，例如“好”“你看”“注意”“诶”“哎呀”“喔”“但是”“问题在于”；这只是转场方式，**最重要的是视角、时间和战术因果**。
- 人工配音或 TTS 推荐使用**独立、清晰的中文赛事解说声线**；若要直接使用真实播音片段、克隆真人音色或暗示官方合作，需另行确认权利与授权。
