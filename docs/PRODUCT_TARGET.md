# 0. 不可曲解的产品目标

用户希望玩到的是：

1. 打开网页，选一支真实俱乐部（如 Vitality、FURIA、Spirit、MOUZ、NAVI），或组建自己的战队。
2. 看见真实选手**职业昵称、国籍、当前战队、已核实的历史效力战队**，不需要真实姓名、出生日期、SteamID、头像，也不需要真人生活资料。
3. 每名选手具有 **12 项 0—100 的游戏能力属性**，不同选手、角色、地图与战术有明显表现差异。
4. 参加具有可信比赛结构的 Major、IEM/BLAST 风格 S 级赛事、A级赛事和小型杯赛；进行抽签、瑞士轮、淘汰赛、地图 Ban/Pick。
5. 一场比赛按照 CS2 回合规则，真实生成首杀、道具、突破、转点、下包、回防、残局、经济、加时、换边等事件。**用户可以每回合选择战术，也可以跳过一个回合、一张地图、一场 BO3/BO5，或一整个无关阶段。**
6. 赛中默认看到的是**连续现场中文解说**：有铺垫、有节奏、有观众视角的判断和情绪反应、能说明“为什么打赢/输了”。后台同时保留精确击杀、伤害、买枪和位置信息；赛后能展开账本，看到自洽的 K/D、ADR、KAST、首杀、残局、地图表现、赛事 MVP、赛季战绩。
7. **战队也有独立的集体数值**（战术熟练、默契、执行、地图准备、沟通、经济纪律、临场调整、胜利信念等），和选手个人能力共同影响每一个回合；**教练有风格和有限次数的暂停**，暂停出现三个与当前比赛相关的可选建议并产生可检验的短期后果。
8. 在生涯模式里经历赛历、获得赛事邀请、改变排名、替换选手、转会并继续下一赛季；沙盒则允许快速自由组队与比赛。
9. **不做**财务、工资、报价、合同谈判数字、赞助、选手伤病、生病、交通、住宿、睡眠、训练课程、真实 3D/2D 战斗画面、联网对战、登录账号、后端 API 强依赖、直播数据同步、赌博系统。

这不是简单的“谁综合战力高，谁就掷骰子获胜”的文字抽奖机。其趣味来自可理解的战术克制、角色搭配、地图池、比赛状态、经济决策与持续赛事故事。

**最高优先级顺序**：真实阵容基础 → 合法的回合与经济/地图事件 → 个人与团队能力共同发挥作用 → 文字解说真实、流畅且绝不造数 → 教练/暂停与战术产生因果效果 → 赛后统计自洽 → 完整赛事/赛季 → 保存与性能 → 精致文字 UI。不要反过来优先做花哨主页。

# 1. 成品形态与技术栈

## 1.1 推荐方案

- Vite + React + TypeScript（strict）+ CSS Modules 或清晰的全局设计令牌；按当前仓库既有技术栈优先，不要为了重构而重构。
- UI 主要使用文字、表格、少量进度条和图标。**没有人物照片、赛场动画、战斗画布，不使用 WebGL。**
- 纯本地单机：游戏启动后离线可玩，真实数据以静态 JSON/TS bundle 提供。不得把数据源的私人 API key 放在浏览器端。
- 游戏逻辑是**无 DOM 依赖的 TypeScript 领域层**；渲染、持久化、数据导入器与随机数彼此解耦。
- IndexedDB 存档（可用轻量封装）；localStorage 只存轻量设置；支持导出/导入带版本的 JSON 存档、重开、删除存档与迁移。
- 长批量模拟使用 Web Worker，并提供进度、取消、错误恢复；主线程不得因为快速模拟一个赛季而长时间卡死。
- 单元/性质测试使用 Vitest；浏览器端到端测试采用 Playwright（环境条件许可时运行）。
- 桌面优先：1440px、1280px、1024px 验收；移动端 390px 要能查看与操作，不强制展示所有表格列。

## 1.2 界面语气

产品风格是**职业电竞比赛指挥台 + 数据分析终端**，不是通用企业后台，也不是游戏直播播放器。

- 深灰/深蓝低对比背景、清晰的层级、可扫描的数据表、醒目的比赛比分与回合决定。
- 关键颜色有稳定语义：己方、对手、经济危险、优势、获胜、失利；不要到处使用霓虹渐变。
- 中文为默认 UI 语言；选手昵称、战队名称、地图官方名称保留英文或常用拼写；电竞术语附短解释（ECO、force buy、KAST、entry、IGL 等）。可扩展英文语言包，但不要牺牲中文完成度。
- **中文现场解说是比赛屏幕主角**，口语化、连续叙事、由局势推进驱动；“完整事件账本”放在次级折叠面板。强调声东击西、读位、经济差、站位、支援与反杀，不强迫用户一直看“谁杀了谁”的流水账。详见 §§4.7—4.15。
- 强调键盘可用性、Tab 焦点、表格可读性、无障碍对比度；尊重减少动态效果设置。所有按钮真的能触发操作，不要虚构“即将开放”菜单。

## 1.3 推荐路由/页面

1. **首页 / 新游戏 / 继续游戏**：最近存档和快速入口；首页需能两次以内点击进入可玩的演示比赛。
2. **选队 / 自建战队**：50 支真实球队、国家/地区、起始排名、五人首发、简要战力；自建队名、地区及从可用人才市场选择五人。
3. **战队管理**：5 首发、候补（可选）、位置/角色分配、战术偏好、地图池、自身变化记录。
4. **选手数据库**：250 人初始真实名单可检索、筛选和排序；12 项能力、角色、地图适应、履历与来源置信度；同时展示战队能力与教练风格。
5. **转会市场**：已签约球员的邀请/交换或自由选手加盟；不涉及金钱，生涯模式有合理规则与结果反馈，沙盒可关闭限制。
6. **赛历/赛事中心**：本周赛程、赛事报名/邀请状态、晋级树、瑞士轮积分、过往冠军。
7. **地图 Ban/Pick**：选择禁图/选图、分析己方对手地图熟练度与先手侧，AI 合法回合操作。
8. **比赛指挥台（核心）**：当前回合、比分、双方 CT/T、真实个人装备/队伍经济、双方可观察情报、地图站位、战术选项、教练暂停、**现场解说主窗**、统计与自动模拟控制。
9. **赛后与历史**：BO 系列比分、每张图比分、选手统计、每轮日志复盘、排名变化、赛事荣誉。
10. **沙盒/设置/存档**：自定队伍/种子/BO 类型/地图/快进、存档导入导出、数据来源/免责声明。

应建立稳定的全局导航和“返回正在进行的比赛”快捷入口，**比赛进行时不能因为页面导航而丢失状态**。

## 2.3 国籍、历史战队、角色来源补齐

采用合法可审计的资料采集流水线，仅补齐游戏必需字段：

1. **官方 VRS 表**：战队、职业昵称、初始名次、初始积分、原始首发五人，作为主键线索。
2. **Liquipedia 选手资料**：国籍、电竞角色（AWPer/IGL/Entry/Rifler/Support，允许多个）、已证实的历史效力队伍、来源页与检索日期。必须遵守其 API 条款。优先复用本地许可允许的数据包而不是在线逐人查询。
3. **现成的职业选手身份数据**：`https://github.com/unicbm/CS2-pro-steamid-lib`。其 `src/cs2_pro_steamid_lib/data/players/liquipedia.jsonl` 数据库约 4.57 MB，包含大量有来源的昵称/国籍/出生信息等记录。**只拿本游戏需要的昵称、国籍、状态等字段**；该仓库的核心目的是 SteamID↔选手身份映射，不能误认为它一定包含完整历史转会表。采集派生数据请遵守仓库 `DATA_LICENSE.md` 和来源归属要求。
4. **PandaScore 或其他具有明确授权的 API**：如现有来源无法补齐，可选；接口可能需要申请 API key、存在字段缺口、访问配额和再分发限制。密钥只能在构建阶段使用，不作为玩家运行游戏的依赖。
5. 无确实来源的历史队伍写 `[]` + `historyCompleteness: "unknown"`，不能自动编造某选手曾在某队服役。昵称重名必须对照官方阵容、所属战队、原始 source ID，不能只用大小写不敏感昵称作为全局唯一主键。

**不可做**：批量抓取 HLTV HTML、绕过其反爬/权限、搬运未经许可的完整数据库/头像；在用户未提供授权时调用商业受限 API；从互联网上复制战队/选手商标图。项目必须包含 `DATA_SOURCES.md`、来源字段和适当署名。可在数据支持下显示真实俱乐部及昵称的纯文字名称，并在关于页明确为非官方粉丝模拟作品。

Liquipedia MediaWiki API 条款官方入口：`https://liquipedia.net/api-terms-of-use`。其公开条款要求限速、识别性 User-Agent、支持 gzip、连接复用及合理缓存；不要浏览器端直连、不要对几千名选手连续猛抓。

## 2.4 数据质量等级

- `verified`：昵称/队伍来自官方 VRS 快照，附源文件和日期；国籍/历史战队单独核对。
- `corroborated`：第二可靠公开源交叉印证。
- `inferred`：仅用于角色或游戏能力建模的推定，不包装成事实。
- `unknown`：真实资料无法确认；显示“资料暂缺”，不要生成假的现实履历。

首版要求：**50 支队伍 × 5 人**的阵容数量、昵称、初始名次齐备且验证；国籍尽最大努力补齐并列出完成率；历史效力队伍允许少量缺失但禁止造假。预先记录缺失率报告；缺失实际历史数据不得阻断比赛引擎。

type Team = {
  id: TeamId;
  name: string;
  region: 'EU' | 'AMERICAS' | 'ASIA' | 'UNKNOWN';
  startingFive: [PlayerId, PlayerId, PlayerId, PlayerId, PlayerId];

# 3. 十二项选手能力系统（0—100）

| 中文 | Key | 核心比赛作用 |
|---|---|---|
| 枪法 | `aim` | 正面对枪、爆头/射击成功倾向 |
| 突破 | `entry` | 首次交火和主动寻找突破口 |
| 狙击 | `awp` | 狙击枪对枪、长距离架点；受购买能力与角色影响 |
| 防守 | `defense` | CT 守点、承受推进、单人拖延 |
| 道具 | `utility` | 闪光/烟火/燃烧弹造成机会和延迟 |
| 战术意识 | `gameSense` | 信息判断、转点、读局、残局选择 |
| 站位 | `positioning` | 架枪、交叉火力、规避被突破 |
| 团队协作 | `teamwork` | 补枪、道具配合、团队执行 |
| 残局 | `clutch` | 1vX 与少打多情境表现 |
| 稳定性 | `consistency` | 限制局间随机波动，而不是无脑增加平均实力 |
| 关键局抗压 | `composure` | 赛点、加时、Major 淘汰局表现波动与稳定 |
| 上限/爆发潜质 | `peakPotential` | **小概率**超常表现，不能使低水平球员频繁秒杀巨星 |

## 3.1 不要主观评价真人智商或性格

这 12 项是**对游戏里比赛能力的建模值**，不是现实人物真实智商、心理健康、人格、道德或私人生活的事实断言。不要给真人贴“心理差”“低智商”等标签。界面设置悬浮解释：“估值为游戏平衡用途，非官方职业测评”。

## 3.2 数值初始化方法

1. 根据团队在固定 VRS 快照的位置建立宽泛的强度先验。
2. 根据公开比赛表现/被核实的职位尽可能细化选手差异；不能获取可靠数据时，使用明确标记的**平衡估值规则**，而不是号称某人真实 Rating。
3. 同一支队伍中的五个人**不能 12 项全一样**；AWPer 与 Entry 应有明显能力侧重，IGL/Support 可有更强的战术/团队维度。
4. 顶级选手要有合理优势，但仍允许小概率发挥失常；弱队有战术爆冷空间。
5. 推荐职业分布大致在 45—97，超级明星可有少数 95+，避免前 30 全员 95 和低排名全员 50 的极端断层；这些是初始平衡建议，不是固定硬阈值。
6. 地图熟练度（0—100）独立；角色适配度与阵容化学反应（轻量）独立，不能成为隐藏的第十三项必填能力。

## 3.3 动态状态与有效实力

- 赛前/赛中可有 `form`（近期状态）、`confidence`（短期信心）、`momentum`（本图节奏），**幅度适中**，防止雪球碾压。
- `consistency` 应主要调节波动方差；`peakPotential` 在适当局面触发罕见的高光修正；`composure` 在赛点等关键局稳定波动。
- 保留每次计算的**结构化能力贡献**：基础枪法、枪械、战术匹配、站位、道具、角色配合、地图熟练、状态、随机项；需要支持赛后“为什么这回合输了”的原因摘要。
- 属性影响必须在同一规则中透明、有上限；不能把 12 项全部加成一次从而重复计算。
- 可在每赛季小幅成长/回归均值，但第一版不需要训练、升级树或 RPG 装备。

## 3.4 团队能力系统（与 12 项个人能力同时运算；本版硬性要求）

**不能只有选手数值。** 团队状态不是五人能力的平均数；名将临时组队会缺少默契，而纸面较弱的长期稳定阵容也可能靠熟练爆弹、同步补枪、换防与经济纪律击败强队。建立以下**八个长期/中期团队参数**，均为 0—100，但用途严格区分：

| 字段 | 解释 | 必须作用于哪些具体事件 | 更新方式 |
|---|---|---|---|
| `chemistry` 阵容默契 | 对熟悉队友行动的预测、角色磨合 | 相邻选手补枪间隔、协同掩护、交叉角配合 | 转会降低，连续比赛缓慢恢复 |
| `tacticFamiliarity[map][tactic]` 战术熟练 | 对某张地图某套既定战术的复现程度 | 预定投掷物时序、集体出枪误差、进攻路由偏差 | 使用战术后缓慢增长，长期不使用轻微衰减 |
| `mapPreparation[map]` 地图准备 | 全队的图池知识和战术储备，而非个人枪法 | 默认守点合理性、预判轮转路线、道具支援到位率 | 赛前配置及比赛经历更新 |
| `execution` 执行力 | 集体行动能否按计划落地 | A/B 爆弹同步、同进同退、回防协调 | 慢变量；受暂停战术调整短期修正 |
| `communication` 信息沟通 | 侦察结果是否准确及时传达 | 正确/错误报点、轮转延迟、队友贸易反应 | 缓慢变化；暂停可减少沟通误差 |
| `adaptability` 临场调整 | 面对变化的纠错、反制能力 | 多轮后改变防区、识别敌方重复战术、改变接触时机 | 赛季缓变，读到战术后小幅临场修正 |
| `economyDiscipline` 经济纪律 | 是否统一起枪、保枪和留钱 | 强起同步率、优先给主狙掉枪、二次起枪计划 | 稳态数值；暂停经济建议短期影响 |
| `belief` 胜利信念 | 动态的比赛士气与信心，不是“选手人品” | 落后/赛点时摇摆、成功翻盘后势头、关键残局稳定 | 每回合缓慢变化并向基准回归 |

**双层映射**：`Player.mapProficiency` 是个人地图经验；`Team.mapPreparation` 是战队集体预案；它们分别进入独立的交锋和执行步骤，避免双重奖励。`chemistry` 与 `execution` 也必须分离：一个主要影响补枪协同，一个主要影响计划兑现，不能两个字段都直接全场 `winChance += 5%`。

- 每支初始真实战队必须有自己的游戏化团队参数，由官方初始排名、阵容是否稳定（若有可信历史证据）、角色互补和可核实的公开资料建立**粗略估值**。没有资料时采用公开、确定性且有随机种子的平衡规则；界面明确标记“游戏估值”。**不要把未经查证的真人性格或教练口碑写成事实。**
- 不允许把团队 8 维、个人 12 维无条件相加；任何影响必须走特定事件的有限幅度权重和软上限。例如默契高让补枪更及时，不等于每次隔烟盲射都必胜。
- 阵容变更立刻更新角色分配与协同关系；长期默契和每套战术熟练按实际模拟比赛逐渐增长；切换地图不复制另一张图的熟练度。
- `belief` 受比赛走向影响但有回归、上限与冷却，连赢十局也不能变成超能力；连输也不能永久失去反抗可能。显示 **战队能力卡**、赛前双方战术倾向比较和每张图的团队准备程度。
- 允许游戏根据对局记录给出“近期五场战术胜率”“本图常用防区”等客观模拟世界统计；不可伪装成现实官方数值。

## 3.5 选手状态、战队状态与教练效果的合成顺序

使用**局部、分阶段的有效能力计算**，不定义玄学通用 `overallPower` 来直接决定回合输赢：

1. 先确定各选手本回合实际枪械、护甲、血量与道具，玩家的 12 属性是基底。
2. 具体角色与地图位置（主狙守远点、步枪突破狭口、支援手补闪）决定哪些属性被激活。
3. 团队默契/地图准备/战术执行改变**计划能否实现、能否及时补枪或轮转**的成功分布，而不是枪械伤害凭空变大。
4. 信念、选手临场手感、教练刚刚选择的暂停建议提供有上限、有截止回合的修正。
5. 最后注入种子可重现的随机扰动；伤害、死亡和终局均由事件记录。

在 `docs/GAME_BALANCE.md` 定义每一效果的**作用点、方向、权重范围、期限、上限与互斥关系**。数值高低必须能被人理解，能够通过 A/B 多 seed 模拟检测到实际差异。

# 4. 核心：有因果关系的逐回合比赛引擎

## 4.1 正确抽象层次

实现一个结构化离散事件模拟器，而不是纯文本故事生成器：

```
地图/BO赛制 → 选边/起始经济 → 回合开始
→ 合法暂停检查（仅回合间 freeze time）：双方教练是否申请暂停、玩家选择三项建议之一
→ 个人资金与历史保枪 → 买枪 / ECO / force buy / 半起 / 全起（考虑双方的真实能力差）
→ 双方**分别且不共享秘密情报**配置战术、站位、分路与节奏
→ 基于地图区域图分配五人初始站位与行进路径
→ 前期控图/投掷物 → 首次接触 → 补枪 → 中期信息战/转点
→ 中后期进攻执行 → 下包/回防/拆包/保枪/爆炸
→ **依据实际终止条件**裁定获胜方；记录结构化因果事件账本
→ 从事件自动汇聚“局势片段”（叙事节拍），再生成**连续中文解说**
→ 结算击杀/伤害/经济/战队动态状态/回合统计/比分；AI 更新已观察到的习惯
→ 下一回合/换边/加时/地图结束/系列结束
```

必须存在可追溯的 `RoundEvent[]`。**先生成合理结构化事件和合法终局，再由事件渲染文字，不允许先随机选一个赢家，再编造与赢家矛盾的事件。**

## 4.2 比赛规则

- CS2 职业模式按照 **MR12**：每半场最多 12 回合，常规赛先到 13 胜；前 12 回合后换边。
- 12:12 后按赛事配置进入加时：推荐职业默认 **MR3**（每次加时 3 回合一边，打 6 回合；3:3 平则继续下一次加时）。不能把每个加时 6 回合误当一张新地图，也不能忘记加时换边。
- 加时经济复位按已核实的赛事规则/可配置值（职业常见 $10,000 起始资金）；不在没有规则来源时宣称所有赛事一致。
- T 获胜：**未下包时**消灭全部 CT，或**下包后**炸弹成功爆炸；CT 获胜：未下包时消灭全部 T 或回合时间结束，或下包后成功拆包。**特别注意：炸弹已下时，即使所有 T 死亡，CT 仍须成功拆包；CT 不得仅凭击杀全部 T 宣告胜利。**
- 回合倒计时、下包后炸弹计时、选手存活状态、剩余生命、购买、持枪与伤害事件必须可检查；任何终局均满足规则条件。
- 1 个回合最多 5 个首发参与每边，不能出场第 6 名；不能重复击杀已死亡选手；不能出现 1v1 时突然 3v2；不能让死者再次击杀、拆包或购买。
- 一张图结束后经济、阵营分配、局内生死状态按下张图规则复位；系列比分与个人系列统计正确累加。
- 团队换边前后能看到 CT/T 侧统计、手枪局、关键经济局的差异。

## 4.3 经济与装备

经济要**影响战术**，但无需实现 CS 全套复杂枪械商城。最小可信模型：

- 5 个选手分别持有资金和当回合装备（pistol/SMG/rifle/AWP/utility/armor/kit 等抽象装备类别），而不是仅一条全队钱包。
- 起始、回合胜负奖励、**连败补助按计数升降**、T 下包奖励、不同枪械的击杀奖励、CT 击杀 T 的团队奖励、存活保枪在可信配置表中处理；数值按核实的职业模式版本集中配置，不允许分散魔法常数。
- `eco`、`halfBuy`、`forceBuy`、`fullBuy`、`awpPriority` 等购买方针必须产生**五人各自合法的实际背包装备**；**缺钱不能强制凭空拿出五把 AWP**。引擎必须单独记录 Kevlar/头盔、拆包钳、主副武器、烟闪燃烧弹、已花费金钱、保留/捡到/丢弃装备。
- 同时考虑枪械类型×有效距离×敌方护甲：AK+全甲对远距离手枪通常优势巨大；**贴烟/箱后近点、交叉枪线、突然横拉、闪光致盲和及时补枪**可以令 Five-SeveN、MP9 等半起装备有合理翻盘机会。弱装备不应被“枪械质量系数”判定为永远无胜算。
- CT 可以在适当情形选择保枪，T 在残局也可保枪；胜负、装备保存、下轮经济必须体现结果。
- 连续输回合与打赢回合会形成经济起伏；好战术可以借助对面 ECO 提高胜率，但不能让 ECO 总是零可能爆冷。**经济规则的版本化细节和独立测试见 §4.9**。

## 4.4 战术引擎：不是按钮上的固定 +5%

建议至少 20 个**有真实战术差异**的候选策略，按双方/地图/经济/局面限制展示：

**T 方进攻策略（建议 12 种）**

1. Default 默认控图与信息试探
2. Fast A 快速 A 区爆弹
3. Fast B 快速 B 区爆弹
4. Slow A 慢速 A 控制
5. Slow B 慢速 B 控制
6. A Split 多线路夹 A
7. B Split 多线路夹 B
8. Mid Control 争夺中路/关键通道
9. A Fake → B 佯攻 A 转 B
10. B Fake → A 佯攻 B 转 A
11. Contact 少道具静步接触进攻
12. Lurk / Pick 分散默认、寻找单点突破

**CT 方防守策略（建议 10 种）**

1. Standard 按地图默认分布防守
2. Stack A 重兵 A
3. Stack B 重兵 B
4. A Aggression A 区前顶
5. B Aggression B 区前顶
6. Mid / Key Lane Contest 争夺中路或关键外场
7. Passive Hold 保守架枪防守
8. Early Info 提前侦察与回收信息
9. Fast Rotate 依侦察提早转点（会被假打惩罚）
10. Retake Setup 放点回防体系

另外提供通用回合指令：`save`、`aggressive`、`conservative`、`balanced`、`utilityHeavy`、`awpFocus` 等，可与合法的站点策略组合。避免 50 个只有名字不同的策略；应明确至少 8 组可测试的克制与反克制关系。

**例**：CT 重 B 遇到真正快攻 B，人数布置与交叉火力有优势；但若 T 用 B 假打并转 A，CT 激进轮转就可能留下 A 空防。CT 中路前压能压制慢速控图，但会被架枪/静步抓单或利用另一侧空缺。AI 的布防不得直接读取玩家本回合尚未执行的秘密策略；只能基于既往回合习惯、地图和可获得信息作预测。

玩家可按回合选择：

- 本回合主体战术（必选，给出“保持上一回合”默认值）；
- 经济方针（支持 AI 推荐）；
- 风险级别（保守/均衡/激进）；
- 是否授权 IGL 自适应（使用其 `gameSense`、`teamwork` 和局势感知加权）；
- 一次点击“执行本回合”。

**不要每 0.5 秒做一次微操选择。** 本游戏是每回合战术选择，局内事件自动演算。高光回合可以展开细日志。

## 4.5 七张真实现役地图——配置驱动

以 2026-10 的 Active Duty 地图池为初版固定快照：

- Ancient
- Anubis
- Cache
- Dust II
- Inferno
- Mirage
- Nuke

官方 2026-07-08 更新曾将 Cache 加入、Overpass 移出。来源：`https://www.counter-strike.net/news/CS2`。

每张地图需要**独立配置**：A/B 区、可用中路/外场/通道标签、双边默认布防、地图 T/CT 倾向、可选战术、角色适应度、关键通道权重、轮转耗时和地图难度。至少区分：

- Mirage：mid / connector / apartments 等；
- Inferno：banana / mid / apartments；
- Nuke：outside、ramp、upper A / lower B，而不是硬套传统 mid；
- Dust II：long、mid、catwalk；
- Ancient：mid、cave、donut；
- Anubis：mid、canals 等；
- Cache：mid、highway、vents 等。

不要出现“不存在的 A/B/中路”叫法。战术应通过地图配置映射到合理位置，地图影响真实演算，而不只是换了背景标题。

## 4.6 结构化交锋与回合状态

每回合建议至少考虑这些因素：

1. 回合经济强度、装备质量、狙击枪是否实际存在；
2. T 的路径、节奏、投掷物投入和进攻站点；
3. CT 的防守人数、交叉火力、前压/回防方案；
4. 地图熟练度及双方地图池偏好；
5. 每个角色与任务的适配程度；
6. 首杀及后续人数优势的自然传播；
7. 道具与信息造成的主动权变化；
8. 战术“读到”或“误读”对方的结果；
9. 关键残局和炸弹处理；
10. 连续重复同一套策略后，对手**基于历史已见回合**作出适度反制。

实现方式允许使用阶段化离散事件，而非模拟 CS2 的弹道/碰撞。概率由选手能力、装备、地图、站位、战术与状态组合得到，经过钳制以避免 0%/100% 的极端常态。不允许对某支真实战队硬编码“剧情胜利”。

**高光机制**：`peakPotential` 和 `clutch` 影响罕见 1vX、连杀、强起逆转；日志必须源于实际事件中的击杀和局面，不允许凭空宣告“ZywOo 五杀”却只有 2 个击杀记录。

## 4.7 文字解说的核心定位：像在看现场，不是在读数据库

> **最高优先级修订**：用户给出的参照是一种“玩机器式”的**高节奏、现场发现、局势反应鲜明的中文解说观感**，不是要求复制、冒用特定真实解说员的声音、署名、固定口头禅或原话。做原创的职业 CS2 文字解说：有“好！这里……”“诶，这个回防……”一类自然口语过渡，但不要每句话机械喊“OK、好、可以看到”。无真人配音、无合成声音；纯文本即可。

- **默认模式是现场口语串讲**：交代交锋背景与经济 → 讲两队的战术意图与站位 → 随事件推进自然评述 → 在真正危险/反转处提升语气 → 赛后给出因果总结。
- **后台必有精确 event ledger**：谁在哪个合法区域、使用哪把实际持有的枪/道具、命中多少 HP、由谁补枪、何时下包/拆包、哪个节点发生轮转。这些是事实源，不需全都堆到直播文字里。
- **普通回合的前台解说**：约 80—220 个中文字符（自适应，并非死规定）；速胜/ECO 可更短；大逆转/关键残局或决胜赛点 180—420 字也可以。输出可按 2—5 个“解说段”渐次显示，**不是固定 5 行有时间戳的击杀流水账**。
- **解说在语义层关注因果**：“为什么这里要重 A？”“B 假打拉动了哪些人？”“孤点站位为什么守不住？”“半起如何利用贴烟位置制造局部两打一个？”“对方什么时候会有一把完整长枪局？”不会每次仅播报 `P1 kill P2`。
- **不要变成小说**：不杜撰心声/私人动机/现实赛事结果，不知道的敌方策略不能在玩家下指令前透露；不渲染未发生的火热反杀或虚构击杀数。
- 设置三个可切换视图：`実況解说`（默认）；`战术复盘`（解释控图、守点、轮转与取胜原因）；`精确事件账本`（时间、区域、道具、伤害、击杀、经济、HP 与统计）。**同一事实源，三种读法**。
- 不引入线上 LLM、第三方文案 API、TTS 或录音作为运行依赖。使用**结构化事件 → 语义节拍 → 场景模板与句式组装**，本地脱机可重播并足够多样。

### 示例：第一张图 Dust II 的手枪局（仅供指导叙事感；虚构模拟，不是现实实录）

**前置账本条件**：FURIA（T）为 FalleN/KSCERATO/molodoy/YEKINDAR/yuurih；Vitality（CT）为 apEX/flameZ/mezii/ropz/ZywOo。FURIA 制定“A 大晚出”，Vitality 在 A 点附近安排三人可形成交叉火力。内部账本必须依次真实产生：ropz 击杀 YEKINDAR → KSCERATO 立即补杀 ropz（4v4）→ ZywOo 合法完成三次击杀（剩 FURIA 的 molodoy，4v1）→ molodoy 杀 mezii（3v1）→ apEX 杀 molodoy（Vitality 以 3 人存活赢下）。若实际模拟并未出现这些事件，**绝不可硬套下述文字**。

> “好！第一张图来到炙热沙城，黑豹先打进攻，小蜜蜂在防守。手枪局 FURIA 没有急着提速，先把 A 大拿住，想打一波晚出。诶！这里长管的闪给过来了，ropz 虽然吃了闪，但他这一枪竟然先点掉了 YEKINDAR！KSCERATO 反应很快，马上补掉 ropz，双方四打四。
>
> 
> 再看 A 平台，小蜜蜂已经把三个人收回来了！这个站位很难进啊，黑豹现在得有人先顶住这条枪线。ZywOo！先点一个，再来一个——第三个也倒了！四打一！molodoy 还在想办法，他反手拼掉 mezii，但 apEX 没给第二次机会。好，这把守下来了，小蜜蜂先拿一分。关键就是 A 平台这个三人的交叉火力，黑豹压过来的时候根本没法一起补枪。”

这是**语气样例**，真正输出必须随实际经济、地图节点、玩家与 AI 的站位、投掷物、击杀人数和结果变化，不强求任何一局出现“三杀”。

## 4.8 解说生产流水线：事件账本 → 局势节拍 → 原创口语

建立明确分层（不得直接在 React 组件里拼出随机台词）：

```ts
type RoundEvent = {
  id: string;
  occurredAtMs: number;                // 回合时间轴，递增；如用剩余时间另存
  phase: 'buy'|'opening'|'contact'|'mid'|'execute'|'postPlant'|'end';
  kind: 'buy'|'coachTimeout'|'tactic'|'position'|'move'|'sight'|
        'info'|'misread'|'flash'|'smoke'|'fire'|'he'|'blind'|
        'duel'|'damage'|'kill'|'trade'|'rotate'|'plant'|'defuse'|
        'save'|'explode'|'timerEnd'|'roundEnd';
  actorId?: PlayerId;
  targetId?: PlayerId;
  teamId?: TeamId;
  zoneId?: string;                     // 必须存在于对应地图的节点图
  weaponId?: string;                   // 必须是实际持有、未丢失的武器
  utilityId?: string;
  damage?: number;
  hpBefore?: number;
  hpAfter?: number;
  playersAliveBefore?: {t:number; ct:number};
  playersAliveAfter?: {t:number; ct:number};
  causeEventIds?: string[];             // 这次转点/伤害/补枪由哪些有效原因触发
  observedBy?: string[];               // 谁实际获取了信息；不等于解说全知视角
  context?: Record<string, unknown>;
};

type CommentaryBeat = {
  phase: RoundEvent['phase'];
  priority: number;                    // 影响篇幅，不影响回合赢家
  category: 'setup'|'economy'|'read'|'entry'|'trade'|'rotate'|
            'hold'|'retake'|'clutch'|'upset'|'close';
  eventIds: string[];                  // 可点开验证的叙事证据
  before: { tAlive:number; ctAlive:number; scoreT:number; scoreCT:number };
  after: { tAlive:number; ctAlive:number; scoreT:number; scoreCT:number };
  facts: Record<string, unknown>;      // 模板使用的结构化、已发生事实
};

type CommentarySegment = {
  text: string;
  emphasis: 'neutral'|'curious'|'tense'|'hype'|'conclusion';
  sourceBeatIds: string[];
};
```

严格按 `simulateRound -> EventLedger -> deriveBeats -> renderCommentary` 生成。`deriveBeats` 是对**已完成的真实事件**聚类：前期布局、谁先拿下关键区域、谁被道具影响、哪次错误轮转、哪里形成局部人数差、残局谁保枪。`renderCommentary` 提供可组合的同义表达、自然节奏和上下文指代。台词顺序必须遵守事件因果，不得偷看未发生的将来以制造“预言成功”台词。

- **观众 / 玩家信息边界**：解说视角可以在回合**已经模拟并逐段揭示时**描述两队的站位（类似直播观赛）；玩家/AI **下回合战术前**的情报面板只能显示合理可观察的过往、经济估算和推断，不能读取敌队下回合隐藏决策。若未来允许回合内微调，则信息权限需更严格分层。
- **谁/哪方/哪点的指代**：维护上一个被提及的队伍、选手、地点、人数与回合经济，不要让连续“他”“对面”“这里”失去指代；可适度使用 FURIA/黑豹、Vitality/小蜜蜂等通行口语别称，在数据中维护别名字典，不凭空乱造。
- **场景词库**：默认抢首杀、首杀被补、三人交叉守点、假打拉扯、道具爆弹、失误轮转、下包、短时间回防、残局 1vX、强起翻盘、残枪保枪、赛点、加时、暂停后战术改变、连胜与连败。针对每种重要节拍至少数个真实不同的句式组合，并随局势限制选用；尽量避免每回合都照搬同一个感叹词。
- **平衡口语与准确度**：只有在事件有证据时说“被闪白”“贴烟”“对枪压住了”“三人回到 A 平台”“站位失误”“两个人拉开补枪”；如果事件里没有这些状态就不能出现。若 2K 也不要喊 3K；1v2 不得喊 1v3。
- **解说随机性完全独立于比赛引擎**：解说句式只使用 `hash(matchId, roundNo, commentaryVersion, beatId)` 派生 RNG；玩家切换解说模式、调整速度/字体、重看文字**不改变任何比赛结果或经济/统计**。
- **因果评论不泄密**：解释结果可以引用已观察到的防区、装备与轮转，不能声称某真人“心态崩溃”“不想赢”这类未经证实的真实心理事实；比赛内的 `belief` 只能描述为“本局模拟士气/战队信念”。
- **解说质量门槛**：以稳定的多场重复回放评估语句重复率、错误时间顺序、指代混乱、缺少亮点、无聊 ECO 冗长、高光局过短、错误地图地点/经济判断。离线规则引擎 + 本地模板为唯一刚需。

## 4.9 经济与起枪系统：逐玩家现金账本，版本化现实规则

**经济是比赛核心，不是“本回合全起=额外 +20%”**。先读取最新官方补丁/赛事配置，落地 `economyRulesetId`，至少支持以下基线（按所选 2026 规则快照进行验证，不可凭记忆瞎改）：

- MR12 每半场第一回合每名选手初始 `$800`，中场换边后重新打手枪局；个人金钱上限常见 `$16,000`；规则来源和核验日写入 `docs/ENGINE_RULES.md`。
- 连败补助按五档阶梯管理（常见 `$1400/$1900/$2400/$2900/$3400`），**赢一回合后连败计数逐级下降而不是全部清零**；回合初始 loss state 与手枪局失败后的补助区别要测试，不能误把手枪局后现金按普通第一败计算。
- 回合结算、下包个人奖金、爆破/拆包奖励、持枪保留、枪械击杀奖励、武器共享/捡枪必须**真实过账**。2024-05-23 Valve 官方将“下包后被拆”时 T 方的团队奖励改为 `$600`，不能拿旧 `$800`；2025-07-15 Valve 官方在竞技模式加入 **CT 每击杀一名 T 就获得 `$50` 团队奖励**。均以相应开关、日期、出处和版本作为规则项。来源见 §17。
- 需要支付的真实装备维度：起始手枪、P250、Five-SeveN、Tec-9、Deagle、MP9、MAC-10、其他 SMG、FAMAS/Galil、M4/AK、AWP，最低限度覆盖；护甲区分**无甲/半甲（Kevlar）/头盔+甲**，加上 CT 拆包钳、烟/闪/HE/火。保留具体枪械的**价格、购买侧、有效距离、护甲穿透、射速、移动惩罚、每杀奖励**。不要求复现全部枪皮与弹道。
- 起枪方案必须从**每个人的现金和已保留装备**约束求解，而不是按队伍总经济直接变出 5 把 AK。默认按团队一致性与预算选择：纯 ECO / 半起 / 强起 / 全起 / AWP 优先 / 调整枪械/道具。模拟队友给主狙起枪时必须一人付钱，另一人接收合法装备，仍需有枪支持。
- 保枪后不得丢失枪却保留原有价值；阵亡不能把已购主武器自动带到下一局；CT/T 换边不能沿用上一方武器库存。经济奖励不能因自动快进二次结算。
- **经济情报属于估计而非读心**：赛前面板显示敌方经济大概（“预计全起/有强起风险/极可能 ECO”，附不确定性与理由）；若未观察到全部敌方武器，不能提前精确显示对方五个人的钱包和装备。解说可以在某位敌人实际露出武器后准确称其携带 Five-SeveN/MP9。

建议 `EconomyLedger` 包含 `cashBefore`、`spend`、`cashAfterBuy`、`loadout`、`killRewards`、`objectiveRewards`、`teamRewards`、`cashAtEnd`、`carriedEquipment`、`lossBonusTierBefore/After`，可逐人展开审查。验收含半起翻盘例：长枪满甲进攻通常能压制手枪/冲锋枪，但贴烟/拐角进攻、被闪、枪线重叠、支援时间足够时，半起防守可依然通过真实多次交火赢局。

## 4.10 地图空间图：A/B 两个按钮远远不够

每张地图必须定义**离散的可通行子区域/战线（zone graph）**，不需要二维物理地图，也不需要人物移动动画：

```ts
type MapZone = {
  id: string;
  cn: string; en: string;
  zoneType: 'spawn'|'lane'|'junction'|'site'|'connector'|'cover';
  siteAffiliation?: 'A'|'B'|'mid'|'neutral';
  size: 'tight'|'normal'|'wide';
  coverRating: number;              // 掩体/非预瞄角保护
  elevation?: 'upper'|'lower'|'level';
  sightlines: Array<{toZoneId:string; range:'close'|'mid'|'long'}>;
  paths: Array<{toZoneId:string; travelMs:number; utilityBlockable:boolean}>;
  closeAngles?: string[];          // 贴烟、门旁、箱后、A 坑等具体玩法条件
};

type PlayerRoundState = {
  playerId: PlayerId;
  side: 'T'|'CT'; zoneId: string; roleAtZone: string;
  hp: number; armor: number; helmet: boolean;
  cash: number; weaponId: string; utility: string[];
  blindedUntilMs: number; smokeObstructedUntilMs: number;
  alive: boolean; hasBomb: boolean; hasDefuseKit: boolean;
  temporaryModifiers: Array<{source:string; expiresAfterRound:number; value:number}>;
};
```

每张图至少覆盖两处包点、关键入口/中路通道、T/CT 起点、可回防的连通路和关键架枪位置，**必须能够让五人分布到具体合法区域**；同一条默认战术在不同地图产生不同人员分配：

- Dust II：T Spawn / Long Doors / Long A / Pit / A Site / Catwalk / Mid / B Tunnels / B Site / CT Spawn / B Doors；能够识别“A 大晚出”“A 短夹击”“B 洞快速爆弹”，并有从 B 转 A 的成本。
- Mirage：A Ramp / Palace / A Site / Mid / Connector / Window / B Apartments / Short / Market / B Site 等；中路得失影响 A/B 路线。
- Inferno：Banana、B Site、Mid、Second Mid、Apartments、A Site、Arch / Library 等；B 香蕉道具争夺关键。
- Nuke：Outside、Secret、Ramp、Hut、Squeaky、Upper A、Lower B、Vents；**上下层**通行和轮转路线必须正确。
- Ancient：Mid、Cave、Donut、A Main、A Site、B Main、B Site 等。
- Anubis：Canals、Mid、A Main、B Main、A/B Site 以及相应连接。
- Cache：Mid、Garage、A Main、Highway、Vents、B Main、A/B Site 等。

允许路线图抽象，但**必须有拓扑关系**：不能瞬间从 B 点传送到 A 点，也不能从未连通的节点隔着地图完成近距补枪。`travelMs`、闪光持续、烟雾遮挡时间和下包/拆包窗口共同决定能否赶到。地图不同（尤其 Nuke）时通用“中路 1 人守”模板必须有映射或禁止。所有中文地名用词来自校验过的 map zone 字典，别在沙二说“香蕉道”、在 Nuke 把 B 当平面的另一个角。

**信息与虚招**：AI/玩家预选 T 方进攻路线和干扰路线；CT 按本队战术先分配 A/B/Mid 人员。声音/烟/投掷物/前顶侦察会产生观测事件，通信传递存在时间与质量；只有观测充分时 AI 才可能快速识破假打。决策不能直接看到对手私有战术；**错误信息与迟疑**能触发错误轮转，使一侧出现空点。

## 4.11 一回合七阶段推演（逐阶段派生，不先定胜者）

1. **Freeze/购买/暂停**：读取上回合银行与经济，双方教练可按剩余暂停、连胜连败、下一局枪局作决策；玩家在有效窗口选择恰好一项暂停建议，更新合法装备。
2. **开局布置**：五人角色、CT 在 A/B/Mid 的人数和具体站位、T 分兵/佯攻/集合、主狙对长短点的选择、地图熟练度与战术准备；隐藏对手尚未暴露的信息。
3. **前期接触**：按可达节点推进，争夺地图控制，烟/火/闪/HE 的实际使用与消耗，闪白、视野遮挡、燃烧延迟、首杀或者未造成击杀的伤害。
4. **中期信息与反制**：某个关键点收到枪声/报点，CT 作出留人/轮转/回防；T 根据已知信息决定真假打兑现、转点、等待残局；这一步的选择必须基于前面事件。
5. **包点执行**：比较实际到点人数、入口与掩体、枪线、道具覆盖、冲点同步，生成独立玩家间交火；失败的突破和及时补枪要被区分。
6. **下包与残局**：满足实际路线和时间后才允许下包；下包后启动 40 秒炸弹计时；CT 根据剩余人数、位置、枪械、拆包钳和时间判断回防或保枪。允许 1vX 成功但概率随具体情况变化。
7. **合法结算**：CT 拆掉包/击杀到满足条件/回合超时，或 T 炸弹爆炸/满足胜利条件；更新两侧经济、保枪、比分、信念、教练效果期限、技术统计与解说事实引用。

需要的交锋模型可示意为：

```text
logit(P(本次交火占优)) = 基准
 + 双方当次相关个人属性差（枪法/站位/狙击/残局等）
 + 双方真实装备×距离×护甲×剩余HP
 + 当前掩体、角度、闪白、烟、火、道具支援
 + 先后手/多人交叉枪线/交易距离和时延
 + 有效战术执行与信息利用修正（团队属性）
 + 当回合状态与有上限的随机扰动
```

它只是**某次实际接触**的模型，不是“整回合胜负概率”。可在既有模型下简化细枝末节，但不得跳过地理位置与库存，或将一方“全甲 AK”写成人人无敌。伤害先减少 HP/护甲，死亡必须先有真实的有效攻击；可有 miss / tag / smoke spam / blind lucky shot / trade 等不同事件。闪白时射击命中倾向显著下滑，但盲射反杀不是逻辑上不可能。补枪必须在短时间/合法邻近战线内；越过一张图的队友不能瞬移来“补枪”。

必须处理 1v4 打成 1v2、选手掉枪后捡枪、掉道具已耗尽、CT 拆包时间（常见有钳 5 秒/无钳 10 秒）、下包前 1:55 回合时钟与下包后 40 秒倒计时；多张图规则数据应可配置并注明来源。不能为了好看故意安排“爆冷”，故事由复杂模拟自然形成。

## 4.12 具体经济/站位互动：半起翻全起的因果示例

**基准局面**：Vitality 作为 T 方，前两局连胜，五人以**实际钱包合法购得**全甲 AK、必要烟闪；FURIA 作为 CT 方，连续失利，本回合部分队员只有 Kevlar + Five-SeveN / MP9，有少量烟闪，队伍采取 B 点低成本近点埋伏。

1. 若 Vitality 走向 B 包点且有可靠闪、火排点和补枪，FURIA 的低装备、缺道具通常会使守点难度上升；**不能靠“守 B 战术 +15”把经济差抹平**。
2. 但若 FURIA 的 Five-SeveN 选手站在实际 B 洞出口的短距离箱后位/烟边，T 方闪光时机失败，进攻者走进近距离迎枪，这名 CT 可基于站位和枪法击杀或重伤一人；其后 MP9 队友如果在合法交易距离内补上第二枪，可将局面改为 5v3 甚至 4v3，改变对方推进。
3. 如果防守通讯良好且从其他区域回防时间足够，回防队友能接管交叉枪位并共同争夺包点；若到达太迟，B 点可能已被下包、CT 应更倾向保枪。**不能把“队友支援快”当作瞬间传送**。
4. 如果半起 CT 击败全起 T，回合结果产生**真实赢回合、捡到的 AK、敌方装备损失、下轮经济变化以及播报中的“强起翻盘”**；若失败，解说须讲清是哪里道具没了、哪个选位暴露了或支援没赶上。

验收需做**配对多 seed 测试**：在相同战队/钱/种子池下，比较“防守近点 + 烟边 + 快速补枪”与“无遮拦单点远距离裸露对枪”的半起局获胜分布，前者应明显改善但都不是确定性；比较完整爆弹与缺乏道具的强攻，前者在优势经济条件下有可测的收益。不能用写死获胜者来通过测试。

## 4.13 回合真值账本与因果链检验

每个 `RoundEvent` 有唯一 ID、合法顺序、状态前后快照、必要时有 `causeEventIds`。至少保留：`roundSeed`、双方**上回合结束现金/背包**、购买后状态、初始战术及站位、双方已知情报、每一次道具消耗、生命/护甲损失、击杀、轮转位置、下包、拆包、保枪、回合结束条件、最终经济和战队动态属性变化。事件流采用**不可变的按序追加**并由 reducer 消费；不允许“解说补一刀”反过来改比赛结果。

硬性校验：

- 一名选手不会从 B 瞬移到 A，或在不连通的位置打出短距击杀；带闪状态/烟遮挡、投掷物库存和武器所有权严格一致。
- 已被击杀者不能进一步买枪/投掷/进攻/下包；玩家击杀不能超过敌方场上实际可死亡人数；多杀和残局从剩余人数计算。
- A/B 站点人数由已记录位置决定；解说如果说“三个人都在 A 平台”，事件快照确实能指出相应三名存活选手。
- 不能一边播报 4v4，一边实时比分板显示 5v3；现场播报与回合事件可以逐段揭示，但关联的是**同一时间轴的即时快照**。
- 没购买却不能突然拿出 AWP/投掷物；经济奖励和支出相加守恒、资金不为负，库存合法；T/CT 只能使用合法侧装备（捡起敌枪除外）。
- `RoundEnd` 后没有该回合新的伤害/击杀/解说剧情；观众展开事件表必能找到播报高光引用的事件 ID。

## 4.14 教练暂停：触发、三选一、反制和回合边界

**教练暂停必须实装**，不是只有一个“暂停 +10% 胜率”的按钮。赛制配置决定地图内可用暂停次数、单次时长、加时补充政策。职业比赛常见每队每图 4 次 ×30 秒，而 FACEIT 的一些默认设置为 3 次：**按赛事模板分别声明，不能宣称全世界统一**。只允许在回合间 freeze/buy 阶段调用，不允许一名选手正在开枪时凭空冻结比赛。默认 v2.0 主要赛事模板：`4 次 / 队 / 图`，OT 是否新增需按赛事配置；历史和回放保留暂停使用原因。

### AI 教练的六种偏好型（可混合权重，而不是分配真实教练隐私人格）

- **止损型 `lossStreak`**：敌方连续得分 2—3 局后更可能请求暂停，优先解决突破口和经济问题。
- **趁势型 `winStreak`**：即使连赢，仍可能为了下轮关键战术、保持专注与避免暴露既有套路而主动叫暂停。
- **后手型 `counterTimeout`**：偏向在对手刚暂停之后观察对方的变化、或下一次合法时点回应；可以选择先不叫以节省次数。
- **经济型 `beforeRifle`**：预计下一回合进入关键完整长枪局/赛点保枪决策时倾向叫暂停。
- **大场面型 `highLeverage`**：关键追分、12:12 加时、Major 生死局、地图赛点时倾向叫暂停。
- **机会型 `stochastic`**：小概率随机触发，但受剩余次数、比赛阶段与策略条件约束，不能无意义乱按。

这些都是**游戏化教练偏好**。除非有严谨公开证据，不能宣称现实某位知名教练“习惯连胜叫暂停/习惯随机暂停”是现实事实。可以在 UI 用“冷静战术家”“节奏型指挥”“情绪稳控者”等虚构档案，不需要真实教练姓名、肖像或语音。首版每支队伍都有可用教练配置，即使没有核实的真人教练资料。

### 暂停界面：系统实时给出三项不同建议，玩家只选一项

建议必须根据**双方经济推测、最近 3—5 回合的进攻路线、手枪/长枪配置、近期失分原因、队伍 `belief`、地图站位、己方阵容与教练擅长点**计算，而不是“攻击 +5/防御 +5/速度 +5”的固定文本。三个推荐必须互不等价，覆盖至少三大方向：

1. **战术与站位调整**：如“连续被 A 大晚出拉扯，下回合保留更多 A 平台交叉枪线；不要过早从中路转 B”。若读对则减少漏点、缩短转点；若敌人改走 B 或假打则可能被克制。必须生成可执行的新战术参数，不只加数字。
2. **士气/心理节奏整理**：如“输了三个长枪局，但两次只是补枪慢，保持耐心；下一轮不要集体赌点”。提高 `belief` 的稳定程度或暂时降低状态波动，幅度有限；不改变个人枪法上限，也不承诺必定逆转。
3. **经济与执行纪律**：如“本回合半起留足下回合 AK/M4 与必要烟闪，先防局部双拉”。推动队员达成同步买枪与道具优先分配，减少半起浪费，调整下一局角色；**不能发额外虚构现金或免费赠枪**。

三个候选可按情境替换文案与精细参数，固定有成本/风险/持续时间（通常 1—3 回合）；玩家可以关闭弹窗、拒绝建议或选择不叫暂停。暂停调用**原子化地扣一次**，不因刷新页面重复扣除。对手 AI 教练独立调用，不预知玩家下一回合私人战术，也可针对玩家过去公开战术进行反制。

### 示例（模拟世界，非现实战况）

```
FURIA 10 : 11 Vitality | Dust II | Vitality 请求战术暂停 [剩余 1/4]
赛况：近 4 局丢了 3 局，连续两次 B 洞防线被一闪突穿。

[1] 收缩 B 区双人交叉：下回合 B 防守更稳，A/中路轮转稍慢
[2] 稳住士气：连续 2 回合削弱失利后的状态波动，局面仍由枪械/站位决定
[3] 调整经济：下回合优先统一长枪+烟闪，当前半起不透支预算

[执行选择] [保持原计划，不用暂停]
```

上述“增加/降低”等效果必须对应实际引擎中的站位、买枪、反应时延或状态项，而不是文本上的承诺。对教练类型运行多 seed A/B：止损型平均更倾向连败后使用；趁势型在连胜期出现一定比例；后手型会有等待/回应；经济型在下把可买全枪时触发率更高。教练暂停整体期望收益不可叠乘成无敌，错误战术调整可能使结果更差。

## 4.15 赛制/选图与教练效果的状态边界

- **BO1、BO3、BO5 是 series 级策略**。赛事的每个阶段允许独立指定 `seriesFormat`：常规小组 BO1、晋级/淘汰 BO3、部分赛事决赛 BO5；还有决赛只 BO3 的赛事。**不要将所有决赛默认 BO5，也不要把 Major 决赛默认为 BO5**。Valve 当前 Major Supplemental Rulebook 指定其淘汰赛全部 BO3；若真实规则变更，变更的是相应赛事模板的规则版本。
- `MapVetoRule` 与 `bestOf` 同时指定，不凭 `bestOf=5` 自动套 BO3 禁选规则。7 图池 BO5 至少保证**恰好 5 张各不相同的地图合法出场**，典型是禁两张留下五张、配置地图先后与选边权；与此不同的真实赛事规则必须由赛事模板声明并且经过测试。
- Valve Major 的 BO1/BO3 **精确 Ban/Pick 顺序**来自官方 Rulebook，优先按其规则建模板；其他比赛按各自规则近似。不得把 Premier 的 2026 年模式直接当成 Major 职业赛 Ban/Pick。
- **每张新图**个人经济、角色 T/CT、信念局内修正、暂停次数与 OT 政策**按照赛事配置复位或结转**，不随意保留上一张图的装备或暂停；团队长期默契与角色职责跨图保留。
- 教练在一张图的剩余暂停不能任意借给另一张图；已使用暂停计数归属于该图与该队，AI 和玩家同一约束。禁止在已经结束的回合追溯插入一次暂停改比分。

# 5. 自动模拟与手动模拟——必须同源

提供下面的明确操作：

- **逐回合**：我来决定战术/购买，点击执行，观察本回合详细日志。
- **自动 N 回合**：例如自动 3 回合、自动到半场、自动至赛点；由 AI 每回合合法选战术与经济决策。
- **模拟整张地图**：走同一个 `resolveRound()`，只隐藏中间日志，不做简化抽签。
- **模拟整场 BO3/BO5**：必须经过真实地图 Ban/Pick、选边、地图经济复位、各张图回合模拟。
- **模拟其他战队**：同一个事件引擎和数值，后台生成结构化结果与统计；展示细节可压缩存储。
- **赛季快进**：按周推进/自动结算其他赛事，必要时 Worker 运行，可取消并保持存档一致。

给用户**开关**：日志精简/正常/详细；自动模拟遇到赛点、加时、残局等暂停并要求玩家接管（可关闭）。

### 关键确定性要求

- 所有随机性只来自注入的可复现 seed PRNG，不要在引擎深处零散调用 `Math.random()`。
- 同一数据快照、同一版本、同一 seed、同一战术决策序列，**手动逐局**和**自动推进**应生成相同的实际胜负、回合结果及选手技术统计。UI 展示不消耗比赛 RNG。
- 保存时记录 PRNG 状态、版本、正在进行的回合阶段、选手状态、赛事状态；重新打开页面继续比赛不应重抽本应固定的结果。
- 支持一键“复制比赛 seed / 重播条件”，便于开发调试和玩家复盘。

# 6. AI 战队的比赛智商

AI 不需要 LLM，也不允许实际调用付费大模型。实现确定性策略引擎：

- 根据己方阵容与位置、金钱、地图熟练度、T/CT 方、领先/落后、对方历史战术分布作概率选择。
- 强队不是每局都选择最优策略；IGL 能力提升对局势信息和战术成功率的利用，但不具备读心/作弊能力。
- AI 可以根据用户频繁 B 快攻作保守的 B 区预判；在未观察到证据前不能总是提前放 4 人 B。
- AI 对资源进行规划：上一局损失、下一局买枪可能性、保枪与爆弹成本。
- AI Ban/Pick 按队伍地图表现、对手弱图、剩余地图与赛制选择，支持小概率保守或策略性意外，不得每场都随机 BAN。
- 用户暂停/接管时，无论选择手动或自动，AI 对手能力保持一致。

## 6.1 AI 战队要先排人，再决定是否转点

对手 AI 的思考顺序是：经济计划 → 布置五个人的合法站位/任务 → 只接收已观察的枪声/烟闪/失点/死亡等事件 → 结合 `communication` 和 IGL 的 `gameSense` 更新 A/B 进攻概率 → 选择留守、支援或反推。**不能直接读玩家本回合秘密的进攻点**，不能自动得知玩家单独拿着什么枪。AI 不仅选择 20 个战术的名字，还应调整具体的站位、烟闪消耗和队内补枪间距。

同一张图里：默认 2A-1中-2B 的合法布局和 3A-1中-1B、1A-1中-3B 应有明显的**站点局部人数后果**；若 T 快打空点，CT 就算队伍实力高，也需要经历真实的回防路程并面对下包后残局。

## 6.2 AI 教练不是胜率作弊道具

- 每个 AI 教练具有固定但可微调的偏好权重、读局水平、暂停保守倾向、战术/心理/经济三个方向的专长；单场决定使用次数不能超过赛事模板。
- 只基于**己方经济和双方可观测对局历史**来识别当前最需要解决的问题。不同教练在连胜、连败、对手暂停、下局买枪、关键局等情境中产生不同叫停概率；不是一模一样地第 8 局和第 16 局必暂停。
- 真实教练姓名不是实现前置依赖，游戏教练画像属于虚构玩法，不宣称现实对应教练有同样心理或行为特征。
- 选择暂停建议后让 AI 自己落实（改变下一轮具体防守分布/购买/短期状态），并在下一回合现场解说中**根据真实实施过程**提到“刚才暂停调整了 B 区站位”等；如果没有调整成功或对手反制，也应诚实播报。

# 7. 赛事系统：职业生涯与真实感资格

## 7.1 双模式

**生涯模式（主要）**：

- 从官方 2026-10-05 真实阵容/排名快照启动一个自洽的游戏世界。
- 赛事按模拟赛季日历分布（建议以周为单位，首版支持至少连续 2 个赛季）。
- 赛季成绩决定下一阶段邀请与世界模拟排名；有地域名额、赛事锁定期、资格淘汰；不能排名最后仍自动受邀所有 S 赛。
- 通过比赛、阵容变更、成绩积累自然产生新强队、黑马和王朝。

**沙盒模式**：

- 任意选择两支真实/自建队、任意合规 5 人阵容；立即设置 BO1/BO3/BO5、地图池、T/CT、赛事模板、seed。
- 自由启动瑞士轮 16 队、8 强淘汰赛、单张图对战、Major 全流程；自由覆盖邀请与转会限制。
- 沙盒成绩不污染已有生涯存档、真实数据基础库或其他赛季。

## 7.2 赛事模板（配置驱动）

不要把真实的某届 2026 赛事日期、真实参赛名单或历史赛果编造出来。允许使用**现实电竞生态常见系列名称作为参考风格的游戏模板**，并清楚标记赛历为虚构模拟；避免未经授权的官方 Logo 与官方合作暗示。

建议首版：

- **Major**：32 队、3 个 16 队瑞士轮 Stage + 8 队单淘汰 Playoffs，赛事层级最高；每模拟年度可有 2 次 Major 风格赛事。
- **S 级 IEM 风格赛事**：16 或 24 队，真实感的小组阶段、淘汰赛、BO3 与 BO5 决赛模板（由赛事配置决定）。
- **S 级 BLAST 风格赛事**：8/16 队小组或淘汰赛、邀请排名门槛；可和 IEM 模板不同。
- **A 级公开赛**：16 队瑞士轮、前 8 晋级；给新兴队伍积分上涨机会。
- **地区杯赛 / 罗马杯式小众杯**：8/16 队单/双败的简化配置；赛历允许不同强度的对手。

一赛季最低交付：1 个可从头到尾游玩的 Major 模板 + 2 个结构不同的 S 级模板 + 1 个 A 级 + 1 个小杯赛；完整赛季应至少生成 12 项分布在不同周的赛事活动（允许模板重复并随机化名称/参赛队伍）。

## 7.3 Major 官方参考模型（不可用旧 24 队版本）

官方参考：`https://github.com/ValveSoftware/counter-strike_rules_and_regs/blob/main/major-supplemental-rulebook.md`

- 32 队：Stage 1 初始 16 队；8 支晋级进入 Stage 2 与 8 支新加入战队组成 16；再 8 支晋级进入 Stage 3 与 8 支新加入战队组成 16；最后 8 强进入淘汰赛。
- 三阶段瑞士轮都以同战绩配对：3 胜晋级 / 3 负淘汰；晋级局和淘汰局 BO3，其他 BO1（依据适用赛事规则模板）。
- 种子、同战绩分组、避免同阶段重复交手、有确定性配对算法；避免配对死循环。
- Major 邀请基于模拟的**地区排名**和名额配置，首季由官方快照初始化；真实 VRS 复杂邀请规则只做**有注明的合理近似**。必要的 `regionAllocation`、完整五人核心、邀请顺位、拒邀补位需配置化。不要谎称完全实现 Valve 官方 VRS 算法。
- 大赛开赛时锁定出赛的五人核心；比赛期间不能利用交易 UI 偷换阵容；合规替补机制可作为未来增强项。
- Playoffs 8→4→2→1，每场 BO3，决赛按赛事配置决定 BO3/BO5，不默默固定一个不经确认的规则。

**配对检验**：同阶段任何一支球队不会重复参与同一轮、绝不出现已经淘汰的队伍重新复活、晋级累计数准确、抽签完整且没有漏组。

## 7.4 地图 Ban/Pick

- 7 地图池；BO1 需逐步禁至 1 图，BO3 需先有禁图再有双方选图、最后余图决定，BO5 应按单独模板配置；关键操作不可超出剩余地图。
- AI 和玩家都必须遵守合法轮次；显示双方每张地图的地图适应和系列形势分析。
- 地图选择方、选边权由赛事配置确定；如实际官方赛事差异较大，明确标记为本游戏的简化赛制。
- 赛前允许地图、首发和角色调整；开赛之后遵守锁阵容约束。

## 7.5 赛季排名、积分、邀请

- 游戏内榜单必须命名为**“模拟世界排名 / 模拟地区排名”**；不能把自己的 Elo/积分公式标成真正的 Valve VRS。
- 可采用以实力先验初始化、比赛结果更新的 Elo/Glicko 或自研稳健评分（需文档说明：强弱对手、赛事权重、地图数、近期赛果、阵容变更的影响）。
- **首季不是所有队伍 0 分，也不是 5 场比赛就让一支垫底队跳到世界第一。** 初始排名权重衰减应适度。
- 赛事冠军、赛区差异、晋级成绩、赛历时间都应能追溯到实际模拟对局。
- 阵容大变动会触发邀请资格重新核查，核心 3/5 连续性规则可依赛事模板近似。
- 排名不是简单的“累计胜场越多越高”，避免靠无限刷小比赛登顶；非生涯沙盒对局不计入排名。

# 8. 轻量阵容管理 / 非金钱转会

**有转会但无金融模拟**。玩家可以：

- 从本队已有五人中指定战术位置、常用 IGL、主狙、突破手、补枪、自由人。
- 查看其他队伍的选手与已核实履历，按角色与游戏数值筛选。
- 洽谈自由选手加盟，或者邀请其他俱乐部在役选手转会；不出现虚构报价、薪资合同的繁琐计算。
- 转会可依据队伍地位、阵容空位、球员是否核心、球队稳定性、玩家成绩判定接受或拒绝。**该机制是游戏化抽象，不代表任何真人真实转会意愿。**
- 允许退队/替换/释放，变动进入双方历史记录；双方阵容变化要影响之后所有场次，不能保留旧首发的幽灵成员。
- 为防止“先买走四个人让对手只剩一人”，生涯模式转会操作只有在交易窗口、两队都有合法五人出战方案时才能最终生效；否则暂存/拒绝、给玩家明确原因。可提供非金钱的直接交换与自由人补位。
- 沙盒自由更换 5 人，不经过转会概率；**永久保持全世界同一选手不能在同一场对决中为两支队伍出场**。
- 首版没有财政、工资帽、合同期限、离职纠纷、选手伤病；`teamChemistry` 只以阵容稳定性和角色协作轻量计算。

**自建战队**：选名称/地区，从未签约人选或沙盒不限池挑五人；若生涯无自由人可选，则允许以“接管并重命名一支现有队伍”启动，保证游戏能实际开始。不能因为没有可用自由人就让创建队伍按钮永久不可用。

# 9. 技术统计与数据守恒

以下统计**必须由结构化回合事件导出**，不允许先随机给比赛比分，再随机生成 K/D 表。

## 9.1 选手维度

- Kills, Deaths, Assists, K/D, K-D, Damage, ADR；
- KAST%（有击杀、助攻、存活或被及时补枪的回合比例，定义交易窗口）；
- Opening kills、opening deaths、opening duel attempts / success；
- Clutch attempts/wins（1v1、1v2、1v3、1v4、1v5）；
- 多杀（2K/3K/4K/5K）、首杀贡献、道具伤害、闪光助攻（若引擎实际支持）；
- CT/T 分边数据、手枪局表现、关键回合表现；
- 每张地图、本场系列、赛事、赛季、职业游戏生涯汇总；
- MVP 与“本局亮点”由明确算法计算，不能只挑声望最大的人。

## 9.2 自定义 Rating

自研并公开定义 `CTM Rating`（例如按每回合击杀、存活、伤害、KAST、关键价值标准化）。**不得误称为 HLTV Rating 2.0 / 3.0**，除非合法获得规范并严格实现。高低合理、可追溯、单张地图与跨图汇总计算一致；缺失基数时显示 `—` 不除以零。

## 9.3 战术和战队维度

- T / CT 胜率、手枪局胜率、force buy / ECO 胜率、炸弹安装/拆除次数、首杀后胜率、4v5 翻盘率、每张图胜率；
- 本场战术使用次数、实际胜率、成功下包、首杀/失误、对手反制信号；
- 每位选手的高光记录、队内贡献；赛季最强图、最薄弱图。

## 9.4 至少遵守的不变量

- 每个死亡须有合理的事件原因；被击杀死亡总量不能超过真实击杀来源与合法非击杀死亡的总和；
- 每个玩家每回合最多被击杀一次，每方同回合场上人数不得超过 5；
- 任何选手单张图的实际参加回合数不得多于地图回合总数；
- 单场 ADR = 已记录总伤害 / 已参加回合；KAST 分子 ≤ 已参加回合；
- 首杀事件每回合最多一个，只有存在实际击杀才可产生；
- 1vX 胜利必须有真实的人员数量状态演进、合法终局；
- 不能有双方都获胜或双方都被判失利的回合；
- BO3/BO5 地图胜数、总回合数、赛事晋级与数据库记载完全一致；
- 半场换边后，同一支球队的 CT/T 身份正确变换；
- 任一赛事淘汰后不得再被下一轮错误安排比赛。

## 9.5 增强战队与教练统计（与叙事事件相互交叉验证）

新增：每图双方**真实暂停使用次数、触发情境、三选一内容、暂停后 1—3 回合执行效果及结果**；团队默契变化、常用战术熟练增长、地图准备程度、爆弹执行成功率、局部补枪效率、A/B 守点成功、从哪条线路转点成功、经济纪律与共同起枪比例。

**停止使用“暂停后胜率变高就证明它有用”作为因果证据**：胜率容易受回归均值影响。平衡测试要用**相同初始状态、多组固定 seed、有/无暂停或选项 A/B 的配对模拟**比较群体指标，不许事后挑对教练有利的回合。比赛历史记录可显示“暂停后 2 回合 1W1L”，但不冒称真实因果。

每段解说都应能点选“关联事件/回合复盘”；任何解说中的击杀数、人数关系、位置、枪械、保枪、经济状态、高潮标记都必须能够在账本得到支持。

- 每回合指令保持上次选择、支持推荐战术与一键默认，不要强迫用户每回合重复点五项。
- 可在新回合前浏览对方经济的**合理推测**与已知地图战术倾向，不能提供 AI 视角下的隐藏确切买枪信息。

- UI 的“比赛已结束/正在比赛”状态清楚；赛后按钮跳转赛历，而不是返回空白首页。
- 大量数据支持筛选、搜索、排序、固定昵称列、移动端横向滚动或卡片替代。
- 无内容与错误状态有具体处理（没有邀请、赛事未开始、阵容不完整、存档损坏、源数据缺失）。
- 不要过度动画、厚重加载页和巨大海报；用户想快速连玩很多比赛。保持可读、冷静的竞技界面。

- 存档 `schemaVersion`、`engineVersion`、`dataSnapshotDate`、`createdAt`、`updatedAt`、`seed` 和 PRNG 状态。
- 用户修改后的球队与选手不能因为更新内置 250 人基础库而被静默覆盖。
- 导入 JSON 需 schema 检验，不能执行脚本/接受原型污染；不信任玩家导入文件。
- 至少 3 个存档槽位，另有沙盒最近对局；支持导出/导入。
- 保存进行中的地图及系列，刷新页面不会丢当局进度或重复颁发奖励。
- 大量他队比赛只保留必要事件摘要与统计，用户比赛保留完整逐回合日志，以控制存档体积。

# 12. 平衡与拟真：可测而非玄学

必须编写校准脚本，对固定版本的大样本 seed 自动运行，而不靠一两场“看起来不错”判断完成：

1. 顶尖战队 vs 顶尖战队，地图胜率不是绝对压制；同实力队打 500+ 图胜率应大致接近 50%（统计误差允许）。
2. 世界前列 vs 第 40—50 队通常有优势，但不能为 100%，且爆冷能够发生。
3. 相同双方/seed，针对特定战术克制的切换，在大量不同 seed 下，**能形成统计上可观测的结果差异**；至少提供 8 组战术 A/B 验证，而不是证明不了谁克制谁。
4. 全起 vs ECO 的群体期望具有明显差异；弱经济方应仍有一定翻盘机会。
5. 爆发局（4K/5K）、残局胜利、完美回合、赛点反超、加时要能自然出现，**不允许强行每局制造高光**。
6. 第一半场与第二半场的经济、换边、地图 CT/T 偏置不能让一方永远以相同比分取胜。
7. 连续模拟 10,000 张图/大量 BO3，不能出现死循环、无赢家、资金负数、死亡人数非法、统计不守恒、比赛不可结束。
8. 同种配置+同种 seed 的回放必须逐事件一致。`auto` 与 `manual` 对相同指令序列的终局必须一致。
9. 形成 `docs/GAME_BALANCE.md`，列清能力公式、参数上限、样本量、异常与尚未达到目标的指标；不要伪造“真实 HLTV 统计对齐”的检验结果。

把校准目标作为合理性参考而非操纵结果的剧本。**禁止为符合胜率目标而直接覆写单场比赛赢家。**

## 12.1 新增平衡矩阵与具体断言

对**装备×距离×人数×信息×地图×团队状态×教练决策**建立至少 12 组可复跑 A/B 场景：

- 长枪五人完整道具默认优于手枪半起五人，但 CT 近点/烟边/交叉火力/及时补枪能提高半起方胜率（非必胜）。
- 同样五位选手、同样个人能力，长期阵容默契高时补枪有效率应优于临时五人组合；不能每次直接多枪命中。
- 同地图同战术，多次有准备的执行与随意站位，在接触时间、道具到位和交叉枪线方面有所差异。
- 高沟通队收到 B 假打消息也可能误判，但误判率与反应延迟应能受可观察信息质量影响；低沟通不是“必定被骗”。
- 路程远的 CT 轮转速度不会超过地图图谱计算的物理最短时间；无法及时回防应发生保枪或战败。
- 暂停选对防守调整时平均改善防点，应付出在另一侧防区人少的代价；错误判断应有被反制概率。
- 经济型教练不会免费生成新资金；相同买枪预算下可提高长枪局同步率。
- 讲解文字的字数、展开级别、重播次数和速度完全不改变 RNG 消耗及本图 K/D、资金、比分。
- 具体 4v4 形成前需要实际 T/CT 各死亡一人；解说“三杀”只有来源事件能统计出三个。
- 手枪局、下包失败、CT `$50` 击杀团队奖、连败阶梯退档、分边换手枪、加时经济均有独立单测。
- 3 次和 4 次暂停两种赛事模板均不超限；在比赛内随意调用暂停被拒绝。
- BO1/BO3/BO5 在不同赛事阶段正确生成合法地图与系列赢图数，BO5 禁选不会复用 BO3 动作。

校准输出包括**样本量、均值、置信区间或不确定性带、随机种子集合、比较说明**。不能只跑三场就宣称“完全拟真”；也不能为了某个预设“黑豹 30% 反杀”强行设立人造赢家。

# 13. 具体端到端玩家体验场景（必须真实验证）

### 测试场景 A：接管 Vitality

1. 从 50 支真实队伍中选 Vitality。
2. 看到 2026-10-05 快照的 apEX、flameZ、mezii、ropz、ZywOo，查看属性与地图池。
3. 选一个可参加的 S 级赛事，查看邀请、分组/淘汰路径。
4. 与 FURIA 比赛，合法完成 BO3 Ban/Pick。
5. Mirage 前 3 回合手动选战术，第 4—6 回合自动，余下模拟到终局；能够中途保存退出再进入。
6. 赛后 K/D、ADR、残局、地图侧统计与事件一致，赛事胜败和排名改变。

### 测试场景 B：弱队挑战 Major

1. 接管第 40—50 名的队伍。
2. 首页不能无视资格直接选择 Major Stage 3；若未获邀，显示资格路径及下一个可报名赛事。
3. 通过较小赛事积累排名，一段时间后满足邀请条件（结果允许失败）。
4. 瑞士轮同战绩配对、3W 晋级 / 3L 淘汰，晋级后只在下一阶段参加一场预定对局。
5. Major 的完整参赛、统计、冠军归档正确。

### 测试场景 C：沙盒梦幻阵容

1. 将来自不同队伍的五位选手组合成自建战队。
2. 选择不同角色与地图、设置 BO5，与任意现役阵容对战。
3. 一键快进系列、查看逐图技术统计、再用相同 seed/相同决策重播。
4. 沙盒结果不改变其他生涯存档和职业世界排名。

### 测试场景 D：转会边界

1. 尝试签下对方唯一有角色适配的主狙；生涯给出合法的转会判定和替代方案。
2. 在 Major 正在进行时换人，应被阻止或在下一窗口生效。
3. 转会完成后所有后续赛事显示新队伍成员，历史阵容记录仍保留原始来源与游戏世界生涯记录。
4. 一名球员不得同时在两支队伍同一场比赛出现。

### 测试场景 E：大批量与保存

1. 自动推进一个完整赛季，包含最低 12 项赛事。
2. 无进度卡死；所有赛事冠军合法；队伍积分/排名自洽。
3. 存档导出、清空、导入、继续下一赛季，得到一致赛季结果。
4. 同样的输入与 seed 产生相同的结果，与 UI 快慢无关。

### 测试场景 F：Dust II 第一回合原创实时解说

1. 选择 FURIA 进攻、Vitality 防守（或交换），指定手枪局及 Dust II 的 A 大/平台真实站位。
2. 观察实际模拟触发首杀/被立即补掉/局部人数 4v4/后续翻转之一（可以固定测试用 seed；**不硬编码正式游戏剧情**）。
3. 默认 UI 不出现单调的 `Player A killed Player B` 长列表，而给出可连续阅读的**中文职业解说段落**，自然交代谁控图、谁在守、打向哪个点、为什么回防/错过时机。
4. 检查它称呼的战队和昵称在初始官方阵容内；说 4v4 时账本恰好各死一人，出现 3K 要有真实三次击杀；即使玩家只看“简精解说”，赛后仍可打开精确事件账本。
5. 重复播放与改变播报速度，胜负/账本/随机流状态逐字节一致。

### 测试场景 G：CT 半起埋伏与全甲 AK 爆弹

1. 设置 Vitality T 方全起 AK/甲/有效烟闪，FURIA CT 方合法半起 Five-SeveN / MP9/有限道具（两队每人钱袋均有守恒）。
2. 让 T 进攻 B，比较 CT 的 B 洞短距站位 + 烟边补枪 vs B 点无遮蔽远距裸枪。多 seed 后前者能提高 CT 局部交火及守点胜率，但装备劣势总体仍合理。
3. 某个合法 seed 若出现强起翻盘，中文解说应说清双方枪械差、FURIA 如何贴烟和补枪、敌方到点人数、关键轮转路线与时间；若输了也应准确描述原因。
4. 确认引擎绝不把无钱 CT 生成 M4/AWP，死者装备不得保留；双方经济因实际战果、击杀与下包结算正确改变。

### 测试场景 H：教练暂停与战队默契的长线影响

1. 用两支相近实力队伍，在多图 BO3 指定不同教练类型（止损、趁势、后手、经济），观察**基于比赛状态**的暂停时机差异。
2. 教练叫停后必须出现**三项贴合实时情况的建议**，实际选择其中一项，正确扣次数并记录其影响范围及过期点。
3. 运行“暂停解读 B 防守”和“暂停稳住信念”等不同决策，能观察到防区人数/状态方差/买枪同步等**不同机制结果**；不是三个按钮都给胜率 +8%。
4. 中途存盘重开/自动继续，暂停计数、建议选择、团队临场变化、AI 教练策略与比分一致。
5. 在交易窗口更换 2 名选手后，团队默契变化影响后续补枪配合，连续多场小幅恢复，已有战术熟练/历史成就不凭空抹掉。
