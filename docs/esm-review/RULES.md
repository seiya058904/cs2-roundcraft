# 比赛阶段计划 plans-1

本规则用于新建的 `causal-plans-v4` 系列赛。它是本项目的区域模拟规则，不是对参考游戏函数体或数值公式的复刻。原有 22 个战术 ID 保留，没有把 576 条配置复制成 576 个玩法。

## 指挥入口与优先级

1. 一键选单个预设，或启用按经济分类的战术池。重新选择单个预设会退出战术池。
2. 展开“阶段调整”，只显示当前阵营能够执行的设置；换边清除阶段覆盖，保留策略选择。
3. 购买和队友发枪结算后，确定实际经济类别，解析并冻结计划。
4. 暂停的重点部署覆盖战术池的预设选择；显式阶段覆盖优先于预设默认阶段。手动站位仅指定初始路线，并非整回合锁定站位。
5. AI 的战术调整只在玩家授权 adaptive 时运行。新版本分析过去的实际目击或公开下包事件，不再读取未观察到的对手预设名称。
6. 路径、存活、烟雾和计时条件限制执行；紧迫时间覆盖等烟和集结等待。已在途的移动不会被新指令瞬移到另一位置。

“执行当前战术/下一回合”采用界面计划。“自动 3 回合/模拟整图/模拟系列赛”仍是原有 AI 接管入口，不宣称自动批量模拟会替玩家重复其手动计划。一次操作模拟完整回合；暂停、快进、详略切换只影响阅读。

## 经济分类与策略池

分类顺序：第 1、13 回合为手枪局；至少四人持步枪/狙击枪且护甲至少 50 为全起；其后优先识别显式强起、eco；其余按实际总支出是否大于人数×1000区分半起与经济局。此分类在购买和发枪后执行，买不起的“全起”不冒充完整装备。50 护甲、四人和 1000 支出均为本项目分档标准。

| 类别 | T 均衡池 | CT 均衡池 |
|---|---|---|
| 手枪 | fastA / splitB | standard / stackB |
| 全起 | splitA / fakeB / slowB | standard / earlyInfo / fastRotate |
| 半起 | contact / splitB | passive / stackA |
| 强起 | fastB / fastA | stackB / aggressionA |
| 经济 | contact / lurk | passive / stackB |

主动施压的全起池改为 T fastA/fastB/splitA，CT earlyInfo/aggressionB/standard；稳健控制的全起池改为 T slowA/slowB/fakeA，CT passive/standard/retake。其他经济类别相同。按本地图此前相同阵营、类别、策略的实际已执行计划计数轮换；暂停覆盖的回合不消耗策略槽位。轮换算法和池内容是项目适配，参考包只证明“按经济类型组织战术列表”的结构。

## 阶段条件与动作

阶段采用已有事件边界：部署、开始推进、下包后。没有照搬参考文本中相互重叠的早中晚秒数。

| 设置 | 条件与实际行为 | 失败或冲突处理 |
|---|---|---|
| 等烟 respect | 下一路径节点有有效烟雾且时间足够，暂停进入该节点；原地仍可交火 | 烟散恢复；等烟加剩余路程/目标操作将超时则立即推进；死亡或回合结束记录中断 |
| 穿烟 cross | 保持原路线穿越烟区，记录 crossing | 不获得命中加成，仍受烟雾视野与交火规则影响 |
| 保留道具 reserve | T 在推进执行前、CT 在下包前，远处接触时暂不消耗道具 | 同区敌人出现，或进入对应执行阶段，解除保留；死亡后不会继续投掷 |
| 正常道具 normal | 沿用接触、熟练度和库存条件 | 没有目标/道具时不能凭指令生成投掷 |
| 集结 regroup | 原定推进时刻为预设 pace+12；至少 ceil(当前存活人数×0.6) 已完成初始路线且不在出生区才直接推进 | 额外等待最多 8 秒；剩余时间不够路程及下包则提前结束等待。60% 和 8 秒是本项目参数 |
| 直接推进 direct | 按原定 pace+12 推进，晚到队员完成当前路径后续进 | 仍受死亡、路径和烟雾条件约束 |
| 轮转 anchor | 沿用实际接触报告、通信延迟和弱侧留守规则 | 过期信息不触发；不读取隐藏 T 目标 |
| 固守 hold | 下包前不进行自动接触支援轮转 | 公开下包后转入回防流程；初始配置与在途移动不被撤销 |
| 回防 save | 沿用人数悬殊、风险、意识和武器价值的保枪判断 | 计时不足仍可保枪；已经身处包点时不会凭此产生传送撤离 |
| 回防 retake | 不因上述人数劣势提前保枪 | 到达加拆除所需时间不够，仍优先保枪 |
| 先清人 clear | 回防时忽略人数劣势保枪，所有 T 倒下后才开始拆除 | 时间不够仍保枪；可能因迟迟不拆而输给计时，不是“更强回防” |

阶段配置拒绝未知键、未知值以及 T 的防守轮转、CT 的进攻集结等不支持组合。导入数据不被 eval，不会执行参考包脚本。

## 事件、解说与版本

阶段动作使用现有 tactic 事件，附 rule/status/reason/version、选手/区域及可用的先行原因引用。等待状态变化只记录一次，回合结束清理未完成状态。实际烟、投掷、移动、伤害和拆包仍使用原领域事件。

回合保存双方解析后的 `plans`，包括版本、经济类别、最终预设、策略槽位及完整默认值，复盘不重新计算策略池。解说从这些事件提取事实，与伤亡共享事件锚点；同一秒按锚点排序。仍保留用户真实语录优先级、语境门槛和“绰号（职业名）”。

无 engineVersion 的旧比赛和 causal-2026-10-v3 保留旧分支，历史事件和赛果不重算。六个旧版本完整比赛哈希见 legacy-fingerprints.json；测试禁止静默刷新该基线。新计划存档缺失或非法会被拒绝，而不是猜测修复。
