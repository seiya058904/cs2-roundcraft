## 发现并拦截的问题

- `extract_meta.py` 以累计顺序分组字段和方法；总数吻合不足以证明归属正确。部分类型出现协程字段或不相干方法，不能构造可信原作调用图。
- `extract_defaults.py` 没有保留可靠的原始类型宽度解码；后续在整数/浮点之间挑“合理值”属于启发式。没有移植这些系数。
- `build_import.py` 从战术名、规则名推算 pace/aggression；没有把结果当成原作参数。
- 7 条 CT 战术 `_43` 引用了 `basic_t_doNotWaitSmoke`。记录为跨阵营命名异常，不直接宣称原作运行 bug。
- `teamcalls.json` 包含规则目录不存在的 `late_t_holdPositions`；alwaysRetake→ReturnToTakeBomb、守包统一指向 A 的映射也不可靠。没有执行该映射。
- 20 处语言键/数字占位符差异。翻译中的“环保圆”“加速道具”“始终重考”等不进入界面。
- 旧设计声称本项目缺少道具、残局能力和地图熟练度，与当前代码不符。保留现有十二项能力、熟练度、武器与燃烧瓶机制。
- 参考包地图含 Overpass/Train，本游戏当前图池含 Cache；不把名称相近视为坐标等价。

## 实际吸收及证据入口

- **阶段独立覆盖**：规则名称和按阶段存储的结构 → 本项目 typed PhaseOverrides/BattlePlan → 烟雾、道具、集结、轮转、回防行为。细节见 [正式规则](RULES.md)。
- **按实际经济组织策略**：StrategyData 的五类列表 → 购买/发枪后分档与可重复轮换。没有引入原作固定槽位数量。
- **执行状态可解释**：TeamCallState 名称提供等待/执行/中断的组织参考 → 本项目事件状态与复盘。不是复制缺失函数体。
- **有证据的 AI 适应**：沿用本项目能力模型，修正新版本 AI 对历史隐藏预设的依赖，只分析可得事件。
- **事实驱动解说**：规则动作与原伤亡事件共享锚点，修复同秒先播阵亡再播先前动作的次序问题。

逐项“来源→证据→含义→缺口→接入→风险→验证→结论”见 `rule-dispositions.json`，所有 52 条都有结论。其他代码模块、数据家族及每文件处置见 `coverage.json`；全量符号、常量、策略、战术和事件图使用同目录 JSON 索引。声明和系统库没有被冒称可复用运行时代码。

## 行为实验而非按钮数量

`phase-experiments.json`：七图、攻守互换、能力与团队值均为 75、角色对齐、同种子配对、全起/经济两类，每项 840 组。对照忽略 tactic/info/sight 日志，仅统计实际行动差异。集结实验两组均使用分路、远端初始路线和等烟条件；不能把其结果概括成普通快攻都受益。

| 对照 | 行为改变组数 / 840 |
|---|---:|
| 等烟 vs 直接穿烟 | 393 |
| 保留道具 vs 正常使用 | 840 |
| 集结 vs 直接推进（阻滞场景） | 16 |
| 固守 vs 信息轮转 | 838 |
| 尽力回防 vs 劣势保枪 | 54 |
| 先清人 vs 尽力回防 | 1 |

改变不意味着胜率提高。完整各图、阵营、经济样本和胜率在报告中；没有人为压到 50%。`behavior-examples.json` 保存具体前后事件，`round-review.json` 保存30个审读回合及原始事实。

## 验收与运行

本地运行：在项目目录执行 `npm run dev`，打开 http://127.0.0.1:5173/。现有进行中旧系列赛不出现新版阶段编辑；新开系列赛使用新引擎。

验证报告见 [VALIDATION.md](VALIDATION.md)。四档截图为 `match-plan-1440/1280/1024/390.png`。旧界面对照沿用 `../evidence/upgrade/match-1440.png`，其拍摄早于本次改动；精确行为对照使用配对事件而非截图推测。

## 剩余缺口

原作源码/函数体、可靠成员所属关系与常量类型不可从当前包补出。混合语料没有完成逐句审读。垂直叠人、假拆诱敌、原作自定义坐标、double pump、主动丢包和精细追击未采用；对应原因均有记录。未伪造球员属性，未扩大经营玩法，未对外发布。

构建通过但入口包略超过 Vite 默认 500 kB 提示；这是体积警告，不是运行失败。没有为消除提示而升级依赖或修改阈值。触屏验收为 Chromium 窄屏/相关滚动自动化，未宣称完成真实手机硬件手感测试。
